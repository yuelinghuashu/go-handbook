# 33 32 压缩与归档

> Go 版本：>= 1.27.1  
> 相关标准库：hash/crc32、compress/gzip、archive/zip、archive/tar

这一篇解决"把数据变小、把多个文件装成一个"的需求，外加校验数据有没有坏。压缩与归档是两层：`compress/gzip` 压缩**字节流**，`archive/zip` 与 `archive/tar` 把多个文件打成**一个归档**；tar 只打包不压缩，所以 `.tar.gz` 是两者套起来用。

## 校验和：hash/crc32

`crc32` 用来做**完整性校验**——检测传输或存储中的意外损坏。它没有任何抗篡改能力，别当签名用：

```go
fmt.Printf("%08x\n", crc32.ChecksumIEEE([]byte("hello"))) // 3610a686
```

数据是流式到来时，用 `crc32.NewIEEE` 边读边累加：

```go
h := crc32.NewIEEE()

h.Write([]byte("hel"))
h.Write([]byte("lo"))

fmt.Printf("%08x\n", h.Sum32()) // 3610a686
```

顺带把另外两个容易混淆的包说清楚：

- **要加密强度的哈希**用 `crypto/sha256`，见 `38-crypto加密与哈希.md`。
- **`hash/fnv` 和 `hash/maphash` 是给“自己实现哈希表、布隆过滤器”的人用的**，应用代码基本用不到：直接用 `map`（见 `08-map.md`）或 `sync.Map`（见 `41-同步原语与内存模型.md`）就够了。这里不展开。

## compress/gzip、archive/zip 与 archive/tar

这三个包解决不同层的问题：`compress/gzip` 压缩字节流，`archive/zip` 和 `archive/tar` 把多个文件打包成一个归档。

## compress/gzip

```go
var buf bytes.Buffer

zw := gzip.NewWriter(&buf)

if _, err := zw.Write([]byte("hello gzip")); err != nil {
    return err
}

// Close 会 flush 缓冲并写入 gzip trailer，错误必须检查
if err := zw.Close(); err != nil {
    return err
}
```

写入端的 `Close` 不是可选的收尾动作，而是**完成压缩的一部分**：它会 flush 尚未写出的数据并补上 gzip trailer。所以不能只写 `defer zw.Close()` 了事：错误会被丢掉，压缩包可能不完整。更常见的坑是 `defer` 让 Close 跑得太晚——如果函数在返回前就要用到 `buf` 的内容（写进文件，或者把它交给调用方），那一刻 Close 还没执行，缓冲数据和 trailer 都还没出现。正确做法是写入完成后立刻显式调用 `Close` 并检查错误。

读取：

```go
zr, err := gzip.NewReader(&buf)
if err != nil {
    fmt.Println(err)
    return
}
defer zr.Close()

data, err := io.ReadAll(zr)
if err != nil {
    fmt.Println(err)
    return
}

fmt.Printf("%q\n", data) // "hello gzip"
```

`gzip.NewReader` 会读取并解析头部，所以它返回 error。另外 `gzip.Reader.Close` 只有在你把内容读到 `io.EOF` 之后才校验 CRC，提前关闭等于没校验。

压缩级别用 `gzip.NewWriterLevel`，可选 `gzip.BestSpeed`、`gzip.BestCompression`、`gzip.DefaultCompression`、`gzip.NoCompression`、`gzip.HuffmanOnly`。

**元数据要写在 `Writer.Header` 上**。gzip 头里可以带文件名与修改时间（`gzip -l` 看得到），默认是空的——想给出文件名就设 `zw.Name`，想固定修改时间（例如为了可复现的构建产物）就设 `zw.ModTime`：

```go
var buf bytes.Buffer

zw := gzip.NewWriter(&buf)
zw.Name = "hello.txt"     // 头里的原始文件名，gzip 用它只是为了展示
zw.ModTime = time.Unix(0, 0) // 固定时间，构建产物才可复现

if _, err := zw.Write([]byte("hello gzip")); err != nil {
    fmt.Println(err)
    return
}
if err := zw.Close(); err != nil {
    fmt.Println(err)
    return
}

zr, err := gzip.NewReader(&buf)
if err != nil {
    fmt.Println(err)
    return
}
defer zr.Close()

fmt.Printf("%q %v\n", zr.Name, zr.ModTime.Unix()) // "hello.txt" 0
```

**读侧有个反直觉的默认行为：一个 `gzip.Reader` 会把多个拼接的成员当成一个流读完**。默认 `Multistream(true)`，所以 `cat a.gz b.gz`、或者同一条流里写了两个 gzip 成员时，会被连续解出来；只想要第一个成员就关掉它：

```go
zr, err := gzip.NewReader(&buf) // 这里的 buf 里放了两段 gzip 数据
if err != nil {
    fmt.Println(err)
    return
}
zr.Multistream(false) // 只读第一个成员；不关的话两段会被拼起来一起读出来

data, err := io.ReadAll(zr)
if err != nil {
    fmt.Println(err)
    return
}

fmt.Println(string(data)) // first
```

压缩格式本身有三个选择：**`compress/flate`** 只有 deflate 数据流、没有头也没有校验和，适合嵌进自定义格式；**`compress/zlib`** 是 deflate + 头 + Adler-32 校验和，跨语言库（Python 的 `zlib`、Java 的 `Deflater`）最常对应它；**`compress/gzip`** 是 deflate + 头 + CRC-32，也是命令行 `gzip`/`gunzip` 认的格式。要和外部工具互通就用 gzip，要自己定义容器格式时用 zlib 或裸 flate。

## archive/zip

```go
var buf bytes.Buffer

zw := zip.NewWriter(&buf)

f, err := zw.Create("a.txt")
if err != nil {
    return err
}

if _, err := f.Write([]byte("zip content")); err != nil {
    return err
}

if err := zw.Close(); err != nil {
    return err
}
```

每个条目的内容必须在调用下一次 `Create`、`CreateHeader` 或 `Close` 之前写完。读取需要注意 `zip.NewReader` 要求 `io.ReaderAt` 和总长度，所以通常是先读成 `[]byte` 或打开文件：

```go
zr, err := zip.NewReader(bytes.NewReader(buf.Bytes()), int64(buf.Len()))
if err != nil {
    fmt.Println(err)
    return
}

for _, zf := range zr.File {
    rc, err := zf.Open()
    if err != nil {
        fmt.Println(err)
        return
    }

    data, err := io.ReadAll(rc)
    rc.Close()

    if err != nil {
        fmt.Println(err)
        return
    }

    fmt.Println(zf.Name, string(data)) // a.txt zip content
}
```

解压不可信归档时要自己校验 `zf.Name` 是否为本地路径（`filepath.IsLocal`），否则可能出现 `../../etc/passwd` 这类路径穿越写文件；zip 条目名也可能含反斜杠。需要设置修改时间、权限等信息时用 `zw.CreateHeader(&zip.FileHeader{...})` 配合 `SetMode`。

## archive/tar

tar 只打包不压缩，所以常用组合是 tar 套在 gzip 外面生成 `.tar.gz`。写入：

```go
tw := tar.NewWriter(&buf)

body := []byte("tar content")
hdr := &tar.Header{
    Name: "a.txt",
    Mode: 0o644,
    Size: int64(len(body)),
}

if err := tw.WriteHeader(hdr); err != nil {
    return err
}

if _, err := tw.Write(body); err != nil {
    return err
}

if err := tw.Close(); err != nil {
    return err
}
```

`Header.Size` 决定这个条目要写多少字节，实际写得比声明少，下一次 `WriteHeader` 就会报错。读取是一个循环，直到 `Next` 返回 `io.EOF`：

```go
tr := tar.NewReader(&buf)

for {
    hdr, err := tr.Next()
    if err == io.EOF {
        break
    }
    if err != nil {
        fmt.Println(err)
        return
    }

    data, err := io.ReadAll(tr)
    if err != nil {
        fmt.Println(err)
        return
    }

    fmt.Println(hdr.Name, hdr.Size, string(data)) // a.txt 11 tar content
}
```

`tar.Reader` 本身就是一个 `io.Reader`，读出来的是当前条目的内容。从磁盘上的文件构造 header 可以用 `tar.FileInfoHeader`。tar 同样要防路径穿越：`Header.Name` 不应包含 `..` 或绝对路径。

**目录和符号链接不能靠 `Name` 表达，要靠 `Typeflag`**。它的零值会被自动提升：`Name` 带尾斜杠就是 `TypeDir`，否则是 `TypeReg`——所以"目录条目要带尾斜杠"不是风格问题，写错会让解压方建出一个同名的普通文件：

```go
var buf bytes.Buffer

tw := tar.NewWriter(&buf)

// 目录条目：显式写 TypeDir，内容长度为 0
if err := tw.WriteHeader(&tar.Header{Name: "dir", Typeflag: tar.TypeDir, Mode: 0o755}); err != nil {
    fmt.Println(err)
    return
}

body := []byte("hello")
if err := tw.WriteHeader(&tar.Header{Name: "dir/file.txt", Mode: 0o644, Size: int64(len(body))}); err != nil {
    fmt.Println(err)
    return
}
if _, err := tw.Write(body); err != nil {
    fmt.Println(err)
    return
}
if err := tw.Close(); err != nil {
    fmt.Println(err)
    return
}

tr := tar.NewReader(&buf)

for {
    hdr, err := tr.Next()
    if err == io.EOF {
        break
    }
    if err != nil {
        fmt.Println(err)
        return
    }

    // 解压侧按 Typeflag 分流：目录、普通文件、符号链接的处理方式完全不同
    fmt.Println(hdr.Name, hdr.Typeflag == tar.TypeDir) // dir true / dir/file.txt false
}
```

符号链接用 `tar.TypeSymlink` + `Header.Linkname`（`tar.FileInfoHeader` 会自动填这两项）。**解压时别按"有没有内容"猜类型**：目录条目的 `Size` 是 0，空文件的 `Size` 也是 0，只有 `Typeflag` 说得清；创建符号链接前同样要检查 `Linkname` 是否指向归档之外，否则又是一个路径穿越入口。
