# 10 指针

> Go 版本：>= 1.27.1  
> 相关标准库：unsafe、reflect

指针只有一个含义：**它是一个变量的地址**。通过地址，你可以做到三件用值做不到的事：

1. **改到调用方的数据**——函数收到的是副本，想改原件就得传地址（`deposit(&a)`）。
2. **改到"切片头"本身**——切片这类类型本身是一个**切片头（descriptor）**，想换掉整个切片头（例如 append 后长度变了）就得传它的地址。
3. **避免复制大对象**——传指针只复制一个地址，传值要把整个对象拷一遍。

反过来说，**不需要这三件事时就不该用指针**。Go 的指针不支持算术（不像 C），所以它的风险主要来自一件事：**nil**。

**"逃逸分析"是性能话题，初读可以跳过**——它回答的是"指针指向的对象被分配在哪"，不影响怎么写对代码。

## 指针是什么

`&` 取地址，`*` 解引用（取出地址上的值）。`p := &x` 之后 `p` 的类型是 `*int`，读作"指向 int 的指针"。下面这段把基本操作和零值一次性演示完：

```go
x := 10
p := &x // & 取地址

fmt.Println(*p)       // 10 —— * 解引用，取回 x 的值
fmt.Printf("%T\n", p) // *int
fmt.Printf("%p\n", p) // 0x… 一个地址，每次运行都不同

*p = 20        // 通过指针写回原变量
fmt.Println(x) // 20

// 声明一个指针不赋值时，零值是 nil
var q *int
fmt.Println(q == nil) // true

// fmt.Println(*q) // panic: invalid memory address or nil pointer dereference
```

三点说明：

- `%v` 打印指针也是一串十六进制地址，但 `%p` 更明确；地址值本身没有意义，**不要依赖它做任何判断**。
- `*p = 20` 改的是 `x` 本身，不是副本，这是指针最主要的价值。
- **解引用 nil 指针会直接 panic**，这是 Go 里最常见的一类崩溃。拿到指针后第一件事永远是问"它可能为 nil 吗"。用 `new`、`&T{}`、或取已有变量的地址得到的指针都不为 nil；nil 只可能来自"声明了没赋值""函数显式返回 nil""从 map/slice 里取出的零值"这几种情况。

## 什么能取地址

先看一个最容易卡住的例子：`&m["a"]` 编译不过，可 `&s[0]` 完全合法——同样是"取容器里某个元素的地址"，为什么一个行一个不行？规则只有一条：**可寻址的值才能用 `&`**，判断标准是"这个值有没有一个可以被指认的位置"。先看合法的写法：

```go
x := 10
p1 := &x // 变量

type Point struct{ X, Y int }

pt := Point{X: 1, Y: 2}
p2 := &pt.X // 结构体字段
p3 := &pt   // 结构体本身

arr := [3]int{1, 2, 3}
p4 := &arr[0] // 数组元素

s := []int{1, 2, 3}
p5 := &s[0] // 切片元素，改它会影响切片
*p5 = 99
fmt.Println(s) // [99 2 3]

p6 := &Point{X: 1} // 复合字面量：唯一的"例外"，但完全合法
fmt.Println(p6.X)  // 1

_, _, _, _ = p1, p2, p3, p4
```

非法的写法编译器会逐个拦下来——**错误信息本身就说清了原因**；其中 map 元素这一条最反直觉，所以顺带给出替代方案：

```go
// &10        // cannot take address of 10 (untyped int constant)
// &(x + 1)   // cannot take address of x + 1 (value of type int)
// &getInt()  // cannot take address of getInt() (value of type int)
// &mm["a"]   // cannot take address of mm["a"] (map index expression of type int)

// map 元素不可寻址，改 map 里的值只有两条路：
type Point struct{ X, Y int }

mm := map[string]Point{"a": {X: 1}}

v := mm["a"] // 1) 取出来、改好、写回
v.X = 2
mm["a"] = v
fmt.Println(mm["a"]) // {2 0}

mp := map[string]*Point{"a": {X: 1}} // 2) 让 map 直接存指针
mp["a"].X = 3
fmt.Println(mp["a"].X) // 3
```

整理成对照表：

| 表达式 | 能否取地址 | 原因 |
| --- | --- | --- |
| 变量 `&x` | ✅ | |
| 结构体字段 `&pt.X` | ✅ | 字段在变量里，有位置 |
| 数组元素 `&arr[0]` | ✅ | 数组是值类型，元素有位置 |
| 切片元素 `&s[0]` | ✅ | 指向底层数组的对应位置 |
| 复合字面量 `&Point{...}` | ✅ | 唯一的例外：字面量会被分配出位置 |
| 指针解引用 `&(*p)` | ✅ | 等价于 `p` |
| 常量 `&10` | ❌ | 常量没有内存位置 |
| 表达式结果 `&(x+1)` | ❌ | 临时值，取完地址就没用了 |
| 函数返回值 `&f()` | ❌ | 同上（这也是 `new` 存在的理由之一） |
| map 元素 `&m["a"]` | ❌ | map 元素会随扩容搬迁 |

## 怎么创建指针

四种写法，选哪个取决于"这个对象从哪来"：

```go
// 1. 指向已有变量：最常见
n := 10
p1 := &n

// 2. 指向新构造的结构体：要初始化字段时最清楚
p2 := &Point{X: 1, Y: 2}

// 3. new(T)：指向一个刚分配的零值 T
p3 := new(int)   // *int，值为 0
p4 := new(Point) // *Point，字段都是零值

// 4. new(expr)（Go 1.26 起）：指向一个值为 expr 的新变量
p5 := new(42) // *int，值为 42

// new(T) 最常见的实际用途：泛型里要一个 *T 的零值容器（泛型语法见 `13-泛型与类型系统.md` 的“类型参数”一节）
func zero[T any]() *T {
    return new(T)
}
```

`&T{...}` 和 `new(T)` 的关系值得说清：`new(T)` 只做"分配并清零"，`&T{...}` 是"先初始化好再取地址"。**两者的结果都是一个指向 T 的指针，逃逸判定规则也一样**，并不必然分配到堆上——是否上堆由编译器决定（见下文"逃逸分析"）。

所以实践中：需要**具体初值**就用 `&T{...}`，几乎总是最清晰的；需要"**就是要一个指向零值的指针**"（例如上面 `zero` 那种泛型容器）才用 `new(T)`。

### new(expr)：Go 1.26 起 new 也接受值

Go 1.26 起 `new` 不再只接受类型，也接受**值表达式**，`go doc builtin.new` 的签名已经变成 `func new(TypeOrExpr) *Type`：

```go
p := new(42)
fmt.Println(*p)                // 42
fmt.Println(reflect.TypeOf(p)) // *int

q := new("hello")
fmt.Println(*q, reflect.TypeOf(q)) // hello *string

// 它分配的是一个新变量，不是 x 本身的地址
x := 7
r := new(x)
*r = 99
fmt.Println(x, *r) // 7 99 —— x 没被改
```

（上面用 `reflect.TypeOf` 确认 `new` 产生的类型；`reflect` 的完整用法见 `36-reflect与unsafe.md` 的“reflect”一节。）

无类型常量会先隐式转换成默认类型（文档原文："If that value is an untyped constant, it is first implicitly converted to its default type."），所以 `new(42)` 是 `*int`、`new(true)` 是 `*bool`；对复合字面量来说，`new(Point{...})` 与 `&Point{...}` 完全等价。

它取代的是以前那个"先复制一份、再取地址"的惯用法，`go fix` 的 `newexpr` 重写器能把旧写法机械地改过来：

```go
// 旧写法：想让指针指向一份独立的副本，只能先造一个临时变量
func intPtr(v int) *int {
    return &v
}

p := intPtr(42)
fmt.Println(*p) // 42
```

`go fix` 的 `newexpr` 重写器会把函数本体和调用点一起改掉，`go fix -diff` 的输出形如：

```diff
 //go:fix inline
 func intPtr(v int) *int {
-    return &v
+    return new(v)
 }

-p := intPtr(42)
+p := new(42)
```

要留意 `new(expr)` 是**语言特性**：`go.mod` 声明的语言版本低于 1.26 会直接编译失败，报错形如 `new(42) requires go1.26 or later (-lang was set to go1.25; check go.mod)`。`-lang` 与语言版本门槛的说明见 `00-工具链.md` 的"语言版本门槛"一节；`go fix -diff`、只跑单个重写器的用法见同一篇的"go fix"一节。

### 逃逸分析

讲完"怎么创建"，自然要问：**这个指针指向的对象，被分配在栈上还是堆上？**答案是编译器的**逃逸分析**（escape analysis）决定的，不是你写 `new` 还是 `&` 决定的：只要编译器能证明一个值的生命周期不超过当前函数，它就留在栈上；一旦它的地址可能"逃"出函数（被返回、存进全局变量、放进堆上的对象、传给接口等），编译器就必须把它分配到堆上，代价是额外的分配和 GC 压力。

```go
//go:noinline
func stackVal() int {
    x := 42
    return x // 没有取地址，x 留在栈上
}

//go:noinline
func heapPtr() *int {
    x := 42
    return &x // x 的地址逃出函数，被迫搬到堆上
}

//go:noinline
func staysLocal() int {
    y := 7
    p := &y
    return *p // 虽然取了地址，但指针没有逃出，y 仍在栈上
}
```

用 `go build -gcflags='-m'` 可以直接看到编译器的判断，输出里只有 `heapPtr` 的 `x` 被标记为 `moved to heap`。两点结论：

- 只是"取了地址"不会导致堆分配，只有地址**逃逸**才会。
- `make`、`new`、`&T{}`、闭包捕获、传给 `interface{}` 等都可能出现在逃逸报告里，说明分配最终由逃逸分析统一裁决。

优化时先写清楚的代码，再在热点路径上用 `-gcflags='-m'` 确认有没有意外的堆分配；不要为了躲避逃逸把代码写得更难懂。`-gcflags` 的完整用法（`-m`、`-m=2`、`-S`）和上面这段的实测输出见 `00-工具链.md` 的"go build -gcflags"一节。

## 用指针做什么

结构体字段也可以是指针，见 `09-struct.md` 的“指针字段”一节。

### 修改调用方的值

Go 的参数传递**始终是值传递**——传进去的是实参的副本。传指针时，复制的是"地址"这个值，但它仍然指向原来的变量，所以函数里改的就是原件。把两种写法并排看最清楚：

```go
type Account struct {
    Balance int
}

// 传指针：改的是调用方的 a
func deposit(a *Account) {
    a.Balance += 100
}

// 传值：改的是副本，调用方看不到
func depositCopy(a Account) {
    a.Balance += 100
}

a := Account{Balance: 100}

deposit(&a)
fmt.Println(a.Balance) // 200 —— 原件被改了

depositCopy(a)
fmt.Println(a.Balance) // 200 —— 还是 200，副本的修改丢了
```

指向结构体的指针有个便利：**可以直接用 `.` 访问字段**，`a.Balance` 是 `(*a).Balance` 的简写，不需要手动解引用。

同样的机制也用在**方法接收者**上，`11-方法.md` 里的 `func (u *User) Birthday()` 与上面 `deposit(a *Account)` 是同一回事——接收者写值还是写指针怎么选，见那一篇的“指针接收者”一节。

### 修改"切片头"本身

切片、map、channel 这类类型本身是一个**描述符**（切片的描述符就是**切片头**：指针 + 长度 + 容量）。传切片时复制的是这个切片头，所以**改元素不需要指针，改切片头才需要**：

```go
// 改元素：不需要指针
func double(s []int) {
    for i := range s {
        s[i] *= 2 // 改的是共享的底层数组
    }
}

// 改切片头本身（长度变了）：需要指针，或者返回新切片
func addOne(s *[]int) {
    *s = append(*s, 4)
}

nums := []int{1, 2, 3}
double(nums)
fmt.Println(nums) // [2 4 6]

addOne(&nums)
fmt.Println(nums) // [2 4 6 4]

// 指针的指针是同一个道理的特例：要改「一个指针变量本身」，就得传它的地址
func reset(p **int) {
    *p = nil // 改的是调用方那个指针变量
}

n := 10
ptr := &n
reset(&ptr)
fmt.Println(ptr == nil) // true
```

多级指针可读性差，能用返回值表达就别用它——`func reset() *int { return nil }` 通常比 `**int` 清楚。切片头的细节见 `07-切片.md`。

### 避免复制大对象

传值会复制整个对象。对象很大时（几百字节以上、或在高频路径上），复制本身就是成本，这时传指针可以避免，但代价是**引入 nil 的可能，以及让被调函数获得修改权**。数组是这里最典型的情况：

```go
// 传数组指针：不复制，而且能改到原数组
func change(a *[3]int) {
    a[0] = 99
}

a := [3]int{1, 2, 3}
change(&a)
fmt.Println(a) // [99 2 3]
```

判断标准：

- **大结构体（几百字节以上）**：传指针通常更划算；但先用 `-gcflags='-m'` 或 benchmark 确认，别凭直觉。
- **小结构体（几个字段）**：传值即可，复制的成本比"多一次间接访问 + nil 检查"更低，语义也更清楚。
- **数组**：数组是值类型，传值必然复制全部元素。大数组要么传指针，要么直接用切片（更常见）。
- **不可变的值**：传值更好，天然没有 nil 问题。

数组的值语义、切片转换、以及"大数组怎么办"的完整讨论见 `06-数组.md`。

## 指针的比较

同类型指针可以用 `==` / `!=` 比较，**比的是地址，不是指向的值**：

```go
x, y := 10, 10
px, py := &x, &y

fmt.Println(px == py)   // false —— 两个不同的变量，地址不同
fmt.Println(*px == *py) // true —— 值相等，但这是值的比较

q := &x
fmt.Println(px == q)   // true —— 同一个变量，地址相同
fmt.Println(px == nil) // false
```

结论：

- **`p == q` 的含义是"两者指向同一个对象"**，不是"两者指向的对象相等"。想比内容要先解引用（并且注意 nil）。
- 指针只能和同类型指针或 `nil` 比较；不同类型之间即使底层相同也不能直接比。
- 函数、map、切片**只能与 `nil` 比较**，不能互相比较（原因见 `12-接口.md` 里"接口比较"一节的相关讨论）。

## 容易踩的点

### 循环变量取地址

Go 1.22 起每次迭代都有自己独立的循环变量，所以在循环里取 `&v`、`&i` 并存起来是安全的，每个指针指向各自那次迭代的值：

```go
var ptrs []*int

for _, v := range []int{1, 2, 3} {
    ptrs = append(ptrs, &v)
}

for _, p := range ptrs {
    fmt.Print(*p, " ")
}
fmt.Println() // 1 2 3
```

Go 1.22 之前所有迭代共用同一个变量，这段代码会打印 `3 3 3`。所以**看旧代码或旧教程时要注意这个语义变化**，自己则有意识地按新语义理解。完整语义见 `03-控制流.md` 的"循环变量"一节。

### unsafe.Pointer 的转换规则

普通 Go 指针之间不能随意转换，也不能做算术。`unsafe.Pointer` 是唯一的例外，它可以在任意指针类型之间转换，但它绕过了类型系统，必须按规矩使用。`go doc unsafe.Pointer` 列出类型 `Pointer` 支持的四种转换：

1. 任意类型的指针值 → `Pointer`
2. `Pointer` → 任意类型的指针值
3. `uintptr` → `Pointer`
4. `Pointer` → `uintptr`

官方文档接着给出了合法的**使用模式**，核心可以概括成三条：

- `*T1` → `Pointer` → `*T2`：要求 `T2` 不大于 `T1` 且两者内存布局等价。`math.Float64bits` 就是这种写法。
- `Pointer` → `uintptr` → 加偏移 → `Pointer`：用于在对象内部移动地址，**两次转换必须写在同一个表达式里**，中间不能把 `uintptr` 存进变量，也不能越过对象边界。

  ```go
  // 模式一：类型重解释（T2 不大于 T1 且布局等价）
  func Float64bits(f float64) uint64 {
      return *(*uint64)(unsafe.Pointer(&f))
  }

  // 模式二：在对象内部按偏移取字段
  type S struct {
      A int32
      B int64
  }

  s := S{}

  // 等价于 &s.B
  pb := (*int64)(unsafe.Pointer(uintptr(unsafe.Pointer(&s)) + unsafe.Offsetof(s.B)))

  // 现代写法：unsafe.Add，语义更清楚
  pb = (*int64)(unsafe.Add(unsafe.Pointer(&s), unsafe.Offsetof(s.B)))
  ```

- `Pointer` → `uintptr`：只用于打印地址，或者作为 `syscall.Syscall` 这类系统调用的实参，且转换必须直接写在调用表达式里。

地址算术和类型重解释之所以被隔离在 `unsafe` 包里，正是因为它们绕过了这些安全检查；日常业务代码基本用不到。

`unsafe.Add`（Go 1.17）、`unsafe.Slice`（Go 1.17）以及 `unsafe.String`、`unsafe.StringData`、`unsafe.SliceData`（Go 1.20）是给这些老套路的现代化替代品：用 `unsafe.Slice(ptr, len)` 从指针加长度得到切片，用 `unsafe.String(ptr, len)` 把字节零拷贝成字符串，用 `unsafe.Add(ptr, offset)` 做偏移。它们的用法、零拷贝转换示例和必须记住的 panic 前提见 `36-reflect与unsafe.md` 的“unsafe”与“内存布局与 unsafe”两节。

最容易出错的一条：指针必须指进一个已经分配的对象，所以不能是 `nil`。

### 一份检查清单

写完涉及指针的代码，回头过一遍这几个问题：

- 这个指针**可能为 nil 吗**？可能就先判空，或者改用值/返回 `(T, bool)`。
- 我传指针是**为了改原件，还是为了省复制**？前者必要，后者要先测。
- 有没有**多个指针指向同一块数据**却当成互不影响？切片、map、结构体字段最容易出这种问题。
- 这个 `&x` 会不会**逃逸**？只在热点路径上关心，用 `-gcflags='-m'` 确认。
- 需要的是**指针还是接口**？想表达"可能是 A 也可能是 B"用接口，`*T` 表达不了多态。

## 使用建议

- 需要修改调用方数据时使用指针。
- 需要修改切片头（descriptor）、map 描述符本身时使用指针（或改用返回值）。
- 大结构体传参时可以使用指针避免复制，但先测量再决定。
- 小结构体或不可变值直接传值：更清楚，也没有 nil 问题。
- 不要为了"看起来像引用"而滥用指针。
- nil 指针需要特别小心，使用前要明确它是否可能为 nil。
- Go 的普通指针不支持指针运算，指针操作比 C 更安全；只有显式使用 `unsafe.Pointer` 才能做地址算术。
- 方法接收者该用值还是指针，见 `11-方法.md`；需要搞清热点路径上的分配来源时，用 `go build -gcflags='-m'` 看逃逸分析结果。
