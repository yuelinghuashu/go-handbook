# 24 时间

> Go 版本：>= 1.27.1  
> 相关标准库：time

时间只有 `time` 一个包，但要解决的问题有四类：**记录一个时刻**（`time.Time`、`Unix()` 时间戳）、**算两个时刻之间过了多久**（`Duration`、`Sub`/`Since`，注意单调时钟）、**格式化成字符串、或从字符串解析回来**（layout、`Parse`/`Format`）、**定时做一件事**（`Ticker`/`Timer`）。四类之间没有依赖，可以按需跳读；`time.Time` 的比较是四类都会踩到的公共问题，见下文的"为什么不要用 `==` 比较 time.Time"一节。

## time.Time

`time.Time` 表示一个时间点。

```go
// Now：当前时间（本地时区，并带单调时钟读数）
now := time.Now()

fmt.Println(now)        // 当前时间，每次运行都不同，还带单调时钟读数（形如 m=+0.000123456）
// Year / Month / Day / Hour / Minute / Second：逐项取出年月日时分秒，同样随运行时刻变化
fmt.Println(now.Year())
fmt.Println(now.Month())
fmt.Println(now.Day())
fmt.Println(now.Hour())
fmt.Println(now.Minute())
fmt.Println(now.Second())
```

### 时间戳

```go
now := time.Now()

// Unix / UnixMilli / UnixNano：自 1970-01-01 UTC 起的秒 / 毫秒 / 纳秒数，与本地时区无关
fmt.Println(now.Unix())      // 秒
fmt.Println(now.UnixMilli()) // 毫秒
fmt.Println(now.UnixNano())  // 纳秒
```

从时间戳恢复：

```go
t := time.Unix(1700000000, 0)
fmt.Println(t) // 本地时区：东八区是 2023-11-15 06:13:20 +0800 CST（UTC 是 2023-11-14 22:13:20），随时区设置而变
```

### 时间计算

```go
now := time.Now()

later := now.Add(2 * time.Hour)
earlier := now.Add(-30 * time.Minute)

fmt.Println(later)   // 当前时间 + 2h
fmt.Println(earlier) // 当前时间 - 30m，同样每次都不同
```

计算时间差：

```go
start := time.Now()

time.Sleep(100 * time.Millisecond)

elapsed := time.Since(start)
fmt.Println(elapsed) // 略大于 100ms（形如 100.123456ms），不会正好等于 100ms
```

### 比较时间

```go
a := time.Now()
b := a.Add(time.Second)

fmt.Println(a.Before(b)) // true
fmt.Println(a.After(b))  // false
fmt.Println(a.Equal(a))  // true
```

`Before`、`After`、`Equal` 之外还有 `Compare`（Go 1.20 起），返回 -1 / 0 / 1，适合做排序：

```go
fmt.Println(a.Compare(b)) // -1
fmt.Println(b.Compare(a)) // 1
fmt.Println(a.Compare(a)) // 0
```

### 为什么不要用 `==` 比较 time.Time

`==` 在语法上是合法的，但它比较的是**整个结构体**，而不是“是不是同一瞬间”。一个 `time.Time` 里装着：

- wall clock 读数；
- 可选的 monotonic clock 读数；
- 以及 `Location`（时区）。

所以同一瞬间用不同时区表示，`==` 就是 `false`：

```go
a, _ := time.Parse(time.RFC3339, "2026-08-28T12:00:00+08:00")
b, _ := time.Parse(time.RFC3339, "2026-08-28T04:00:00Z")

fmt.Println(a == b)        // false —— 同一瞬间，但 Location 不同
fmt.Println(a.Equal(b))    // true
fmt.Println(a.Compare(b))  // 0
```

带 monotonic 读数的时间也一样：

```go
now := time.Now()

fmt.Println(now == now)              // true
fmt.Println(now == now.Round(0))     // false —— Round(0) 去掉了 monotonic 读数
fmt.Println(now.Equal(now.Round(0))) // true
fmt.Println(now == now.UTC())        // false —— Location 和 monotonic 读数都不同
```

结论：

- 判断“是不是同一瞬间”**永远用 `Equal`**，它会在双方都有 monotonic 读数时用最精确的比较；
- 需要大小关系时用 `Compare`（约定和 `cmp.Compare` 一致），不要用 `Before`/`After` 两个调用去拼三段式；
- `==` 只在确实想比较“结构体完全一致”时才有意义：两个值都已经 `UTC().Round(0)` 归一化过，或者和零值比较（后一种场合用 `IsZero()` 更明确）；
- `time.Time` 不要直接当 map key 或数据库 key。真要用，先归一化：`t = t.UTC().Round(0)`，保证所有值的 `Location` 一致、并剥掉 monotonic 读数。

### 单调时钟（monotonic clock）

`time.Now()` 返回的值同时带 wall clock 读数和 monotonic clock 读数。规则是：**报时间用 wall clock，量时间用 monotonic clock**。

- `Sub`、`Since`、`Until`、`Before`、`After`、`Equal`、`Compare` 在双方都带 monotonic 读数时**只用 monotonic**，所以计时过程中系统墙钟被 NTP 校正也不会算出负数；
- 只要有一方没有 monotonic 读数，这些操作就退回比较 wall clock；
- `AddDate`、`Round`、`Truncate` 是 wall time 运算，**总会去掉** monotonic 读数；`In`、`Local`、`UTC` 也会去掉。剥离 monotonic 的惯用写法是 `t = t.Round(0)`；
- 序列化（`MarshalJSON`、`MarshalText`、`MarshalBinary`、`GobEncode`）不带 monotonic 读数，反过来 `Parse`、`ParseInLocation`、`Date`、`Unix` 以及各种 Unmarshal 也都不产生 monotonic 读数。`time.Time` 的 JSON 编码细节（RFC 3339、`omitempty` 陷阱）见 `26-JSON与序列化.md`。

所以“序列化再解析回来”的时间与原值 `==` 为 `false`：

```go
t := time.Now()

b, _ := t.MarshalText()
var t2 time.Time
_ = t2.UnmarshalText(b)

fmt.Println(t == t2)     // false —— monotonic 读数没了
fmt.Println(t.Equal(t2)) // true
```

另外，某些系统休眠时 monotonic 时钟会停走，此时 `t.Sub(u)` 不再等于真实经过的时间，需要改用剥掉 monotonic 的 wall clock 计算。

## 格式化与解析

Go 使用固定参考时间：

```text
2006-01-02 15:04:05
```

这个字符串是**参考时间本身**，不是占位符。layout 里出现的 `2006`、`01`、`02`、`15`、`04`、`05` 分别代表年、月、日、24 小时制小时、分钟、秒。

所以 `YYYY-MM-DD` 这种“看起来像格式”的写法不成立，它会被当成字面量去逐字匹配：

```go
t, err := time.Parse("YYYY-MM-DD", "2026-08-28")

fmt.Println(t)   // 0001-01-01 00:00:00 +0000 UTC
fmt.Println(err) // parsing time "2026-08-28" as "YYYY-MM-DD": cannot parse "2026-08-28" as "YYYY-MM-DD"
```

格式化：

```go
now := time.Now()

s := now.Format("2006-01-02 15:04:05")
fmt.Println(s) // 当前时间按这个 layout 格式化
```

解析：

```go
t, err := time.Parse("2006-01-02", "2026-08-28")
if err != nil {
    return err
}

fmt.Println(t) // 2026-08-28 00:00:00 +0000 UTC —— 不带时区信息时按 UTC 零点解析
```

解析本地时间：

```go
loc, err := time.LoadLocation("Asia/Shanghai")
if err != nil {
    return err
}

t, err := time.ParseInLocation("2006-01-02 15:04:05", "2026-08-28 12:00:00", loc)
fmt.Println(t) // 2026-08-28 12:00:00 +0800 CST —— 按给定时区解析
```

### 常用 layout 常量

手写 layout 容易打错，标准库已经给常用格式准备了常量：

```go
time.RFC3339     // 2006-01-02T15:04:05Z07:00
time.RFC3339Nano // 2006-01-02T15:04:05.999999999Z07:00
time.DateTime    // 2006-01-02 15:04:05
time.DateOnly    // 2006-01-02
time.TimeOnly    // 15:04:05
```

`DateOnly`、`TimeOnly`、`DateTime` 是 Go 1.20 新增的。用法：

```go
t := time.Date(2026, 8, 28, 13, 45, 30, 0, time.UTC)

fmt.Println(t.Format(time.DateTime)) // 2026-08-28 13:45:30
fmt.Println(t.Format(time.DateOnly)) // 2026-08-28
fmt.Println(t.Format(time.TimeOnly)) // 13:45:30
```

用固定时间而不是 `time.Now()` 作为输入，输出才是可复现的。

序列化给外部系统时优先用 `time.RFC3339`（带时区偏移，信息完整）。

## Duration

`time.Duration` 表示时间段：

```go
d := 2*time.Hour + 30*time.Minute

fmt.Println(d)                // 2h30m0s
fmt.Println(d.Seconds())      // 9000
fmt.Println(d.Milliseconds()) // 9000000
```

常用常量：

```go
time.Nanosecond
time.Microsecond
time.Millisecond
time.Second
time.Minute
time.Hour
```

### 解析 Duration 字符串

配置项里的 `"1h30m"` 用 `time.ParseDuration` 转成 `time.Duration`：

```go
d, err := time.ParseDuration("1h30m")
if err != nil {
    return err
}

fmt.Println(d)           // 1h30m0s
fmt.Println(d.Minutes()) // 90
```

合法的单位只有 `ns`、`us`（或 `µs`）、`ms`、`s`、`m`、`h`；不识别 `d`、`w` 这类单位：

```go
_, err := time.ParseDuration("1d")
fmt.Println(err) // time: unknown unit "d" in duration "1d"
```

反方向用 `d.String()`（`fmt.Sprint(d)` 等价）把 `Duration` 变回字符串。

## 构造、截断与日期加减

`time.Date` 显式构造一个时间点，越界的字段会被规范化：

```go
t := time.Date(2026, 8, 28, 13, 45, 30, 0, time.UTC)

fmt.Println(t.Format(time.DateTime)) // 2026-08-28 13:45:30

// 10 月 32 日会被规范化为 11 月 1 日
fmt.Println(time.Date(2026, 10, 32, 0, 0, 0, 0, time.UTC).Format(time.DateOnly)) // 2026-11-01
```

`Truncate` 向下取整到某个 `Duration` 的整数倍，常用来对齐到天/小时边界：

```go
fmt.Println(t.Truncate(24 * time.Hour).Format(time.DateTime)) // 2026-08-28 00:00:00
fmt.Println(t.Truncate(time.Hour).Format(time.DateTime))      // 2026-08-28 13:00:00
```

倍数是从**零时刻**算起的绝对偏移，不是“显示上的对齐”，所以在非整小时时区（如印度 +05:30）里 `Truncate(time.Hour)` 得到的小时字段不一定落在整点；同理 `Round(time.Hour)` 也可能返回非零分钟。`Truncate(0)` / `Round(0)` 只是剥掉 monotonic 读数。

`AddDate` 做年/月/日的日历运算，同样会规范化：给 10 月 31 日加一个月得到 12 月 1 日。

```go
d := time.Date(2026, 10, 31, 0, 0, 0, 0, time.UTC)
fmt.Println(d.AddDate(0, 1, 0).Format(time.DateOnly)) // 2026-12-01
```

日历运算和时区耦合：`AddDate(0, 0, 1)` 是“明天的同一时刻”，跨夏令时切换时并不是固定的 24 小时。需要精确时长请用 `Add`。

## 定时器与周期任务

```go
timer := time.NewTimer(time.Second)
defer timer.Stop()

<-timer.C
fmt.Println("timeout")
```

```go
ticker := time.NewTicker(time.Second)
defer ticker.Stop()

for t := range ticker.C {
    fmt.Println(t) // 每秒打印一次当前时间，每次不同；这个循环不会自己结束
}
```

`time.After` 是一次性的简化写法：

```go
select {
case <-time.After(time.Second):
    fmt.Println("timeout")
}
```

### 定时器的回收（Go 1.23 起）

`time.Tick` 和 `time.After` 的“会不会泄漏”在 Go 1.23 变了，`go doc time.After` 和 `go doc time.Tick` 现在都写明了这一点：

- Go 1.23 之前，`time.Tick` 底层的 Ticker 永远不会被 GC 回收；`time.After` 的 Timer 在触发前也不会被回收。文档当时建议改用 `NewTicker`/`NewTimer` 并手动 `Stop`。
- Go 1.23 起，GC 能回收**没有任何引用且未 Stop** 的 timer/ticker；文档现在的措辞是“There is no reason to prefer NewTimer when After will do”。

所以在 `select` 里直接用 `time.After` 已经是可接受的（不会因为没 `Stop` 而长期占用资源）：

```go
select {
case <-time.After(time.Second):
    fmt.Println("timeout")
case <-done:
}
```

两点仍然要注意：

- 循环里反复创建 timer 依旧是白白的分配开销，固定周期的任务用 `NewTicker` + `defer ticker.Stop()` 更清楚，也更好控制停止时机；
- `time.Tick(d)` 在 `d <= 0` 时返回 `nil` 通道（`NewTicker` 会 panic），从 `nil` 通道接收会永远阻塞。

## 选择与坑

前面四类任务各自的选择，集中成一张清单（每条在上文都有出处，这里只做索引）：

- **比较"是不是同一瞬间"用 `Equal`，要大小关系用 `Compare`**，不要用 `==`——`==` 会连 `Location` 和单调时钟读数一起比，得先 `UTC().Round(0)` 归一化才说得清（见 `24-时间.md` 的"为什么不要用 `==` 比较 time.Time"一节）。
- **量经过的时间用 `time.Since(start)`**，而不是 `time.Now().Sub(start)` 的两次取时钟；两者都走单调时钟，但 `Since` 少一次 `Now`，意图也更清楚。
- **报时间用 wall clock，量时间用 monotonic clock**：`AddDate`/`Round`/`Truncate`/`In`/`UTC` 以及所有序列化都会剥掉单调读数，别把序列化后的时间拿来做时长计算（见"单调时钟（monotonic clock）"）。
- **格式化与解析都写 layout 常量**（`time.RFC3339`、`time.DateTime`…），不要手写 `"2006-01-02"` 以外的自定义格式；parse 出来的是 UTC 还是本地时区取决于用 `Parse` 还是 `ParseInLocation`。
- **固定周期用 `NewTicker` + `defer ticker.Stop()`**；`time.After` 在 `select` 里可以直接用（Go 1.23 起不再有 GC 顾虑），但循环里反复建 timer 仍有分配开销。
