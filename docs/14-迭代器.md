# 14 迭代器

> Go 版本：>= 1.27.1  
> 相关标准库：iter、slices、maps

读之前需要先掌握泛型——`iter.Seq` 本身就是泛型类型，见 `13-泛型与类型系统.md`。

## 迭代器函数：把 `yield` 传进去，而不是把值取出来

标准库 `iter` 定义了两个基本类型：

```go
type Seq[V any] func(yield func(V) bool)
type Seq2[K, V any] func(yield func(K, V) bool)
```

`Seq[V]` 产出单个值，`Seq2[K, V]` 每次产出两个值（遍历 map 的键值对、切片的索引元素就是后者的常见形状）。它们都只是函数类型，所以任何签名匹配的函数都能直接 `range`。

## 自己写一个迭代器：`yield` 返回 `false` 就得停

下面是一个最简单的迭代器，它把同一个字符串重复 `n` 次：

```go
func Repeat(s string, n int) iter.Seq[string] {
    return func(yield func(string) bool) {
        for range n {
            if !yield(s) {
                return
            }
        }
    }
}

for s := range Repeat("go", 3) {
    fmt.Println(s) // go（共 3 行）
}
```

它是个"推"风格的迭代器：`range` 在背后调用这个函数，并传入一个 `yield` 回调；迭代器每产生一个值就调用一次 `yield`。

`yield` 返回 `false` 表示调用方提前结束了遍历（循环里 `break`、`return`，或者 `yield` 后面的语句不再需要执行），**迭代器应当立刻停止**。上面那句 `if !yield(s) { return }` 就是这条约定，自己写迭代器时不能省——省掉它，调用方 `break` 之后迭代器还会继续空转。

`iter.Seq2` 一次产出两个值，例如同时给出索引和元素：

```go
func Enumerate(words []string) iter.Seq2[int, string] {
    return func(yield func(int, string) bool) {
        for i, word := range words {
            if !yield(i, word) {
                return
            }
        }
    }
}

for i, word := range Enumerate([]string{"a", "b"}) {
    fmt.Println(i, word) // 0 a / 1 b
}
```

写迭代器时注意：`yield` 有可能在任意一次调用后要求停止，所以迭代器内部**不要缓存跨 `yield` 的可变状态**再去假设它会一直跑完；有清理逻辑时，把它放在 `defer` 里，`return` 和正常结束两条路径都会走到。

## 拉取式迭代：`iter.Pull` 把推式转回拉式

上面的迭代器都是"推"风格：由迭代器把值推给 `yield`。`iter.Pull` 可以把它转成"拉"风格，得到 `next` 和 `stop` 两个函数：

```go
next, stop := iter.Pull(Repeat("go", 3))
defer stop()

for {
    s, ok := next()
    if !ok {
        break
    }
    fmt.Println(s) // go（共 3 行），与推风格的结果一致
}
```

`next` 每次取出一个值，第二个返回值为 `false` 表示序列已经结束；结束之后或调用 `stop` 之后再调 `next`，仍然返回零值和 `false`。`stop` 用于在序列还没结束时提前收尾，标准写法是 `defer stop()`。

`iter.Seq2` 对应的是 `iter.Pull2`，`next` 一次返回两个值和一个 `bool`：

```go
next, stop := iter.Pull2(Enumerate([]string{"a", "b"}))
defer stop()

i, word, ok := next()
fmt.Println(i, word, ok) // 0 a true
```

`next` 和 `stop` 都不是并发安全的，不能在多个 goroutine 里同时调用。只有在需要手动一步步取值（例如想把迭代器和别的数据源放进同一个 `select`）时才需要 `Pull`；普通遍历直接用 `range` 更清楚。

## 能不能重复遍历，取决于迭代器本身

**不要假设"迭代器 = 只能遍历一次"，也不要假设"迭代器 = 可以反复遍历"。**`go doc iter` 把这条约定写得很清楚：

> Most iterators provide the ability to walk an entire sequence: when called, the iterator does any setup necessary to start the sequence, then calls yield on successive elements of the sequence, and then cleans up before returning. **Calling the iterator again walks the sequence again.**
>
> Some iterators break that convention, providing the ability to walk a sequence only once. These "single-use iterators" typically report values from a data stream that cannot be rewound to start over. Calling the iterator again after stopping early may continue the stream, but calling it again after the sequence is finished will yield no values at all. Doc comments for functions or methods that return single-use iterators should document this fact.

也就是说分两类：

**（一）大多数迭代器可以重复遍历**，每次调用都从头开始。`slices.Values`、`slices.All`、`slices.Backward`、`slices.Chunk`、`maps.All` 都是这一类——它们只是把底层容器的遍历包了一层，没有自己的状态：

```go
seq := slices.Values([]int{1, 2, 3})

for v := range seq {
    fmt.Print(v, " ") // 1 2 3
}

for v := range seq {
    fmt.Print(v, " ") // 1 2 3 —— 又一次从头开始
}
```

**（二）单次迭代器（single-use iterator）只能走一遍**，典型来源是"无法回退的数据流"：网络连接、文件读取器，以及 `strings.SplitSeq`、`strings.Lines` 这类流式分割函数（`strings`/`bytes` 里哪些函数属于这一类，见 `20-字符串与字节.md` 的“迭代器版分割 API（Go 1.24）”一节）。

自己写一个单次迭代器很简单——状态留在闭包外面就行：

```go
func Drain(s []int) iter.Seq[int] {
    i := 0
    return func(yield func(int) bool) {
        for ; i < len(s); i++ {
            if !yield(s[i]) {
                i++ // 让下一次从下一个元素继续
                return
            }
        }
    }
}

seq := Drain([]int{1, 2, 3, 4})

// 完整走完一遍
for v := range seq { fmt.Print(v, " ") } // 1 2 3 4
// 再遍历：什么都不产出，元素已经被取走了
for v := range seq { fmt.Print(v, " ") } // （空）

// 换一个：这次走一半就 break
seq2 := Drain([]int{1, 2, 3, 4})
for v := range seq2 { fmt.Print(v, " "); break } // 1
// 再遍历：从上次停下的地方继续，而不是从头开始
for v := range seq2 { fmt.Print(v, " ") } // 2 3 4
```

所以对单次迭代器，**再次遍历的行为没有保证**：可能什么都不产出，也可能接着上次的位置往下走，取决于它内部还剩什么状态。判断办法只有一条：**看这个迭代器的文档有没有写 single-use**。没写就按可重复遍历理解，但也不要依赖"遍历到一半再重新开始"这种用法。

需要多次遍历或需要保存结果时，最稳妥的做法是先 `slices.Collect` 收成切片，或者干脆把构造迭代器的那次调用重新执行一遍（每次拿一个新的、干净的状态）。

这条约定也是迭代器比"先构造切片再遍历"省分配的原因：`for range` 里 `break`/`return` 提前结束时，剩余元素根本不会被产出，也就不会有对应的分配。

### 写迭代器时的两条硬约束

自己实现 `iter.Seq` 时：

- **`yield` 返回 `false` 之后不能再调用它**——`go doc iter` 的原文是 "Yield panics if called after it returns false."，所以上面每个例子里那句 `if !yield(v) { return }` 都不能省。
- 返回单次迭代器时，**在文档注释里写明**，并在文档里说明它不能被重复遍历。

## 标准库里的迭代器

### slices

`slices` 提供了几个把切片变成迭代器的函数：

```go
s := []int{10, 20, 30}

for i, v := range slices.All(s) {
    fmt.Println(i, v) // 0 10 / 1 20 / 2 30
}

for v := range slices.Values(s) {
    fmt.Println(v) // 10 / 20 / 30
}

for i, v := range slices.Backward(s) {
    fmt.Println(i, v) // 2 30 / 1 20 / 0 10 —— 索引也跟着倒着来
}
```

`Chunk` 把切片按固定大小分块，每次产出一个子切片（Go 1.23 起）：

```go
s := []int{1, 2, 3, 4, 5}

for chunk := range slices.Chunk(s, 2) {
    fmt.Println(chunk)
}
```

输出：

```text
[1 2]
[3 4]
[5]
```

`slices.Sorted` 是"排序 + 收集"的一步写法（Go 1.23 起）——它把迭代器中的元素排序后返回切片，等价于 `Collect` 之后再 `Sort`：

```go
result := slices.Sorted(slices.Values([]int{3, 1, 2}))
fmt.Println(result) // [1 2 3]
```

### maps

`maps.Keys`、`maps.Values`、`maps.All` 返回的同样是**迭代器**而不是切片（Go 1.23 起），要真的拿到切片必须先 `slices.Collect`——签名形状、`golang.org/x/exp/maps` 那段历史、以及需要稳定顺序时的写法，见 `16-maps.md` 的“返回的是迭代器（Go 1.23 起）”一节。

### strings 与 bytes

`strings` 和 `bytes` 也有一组返回迭代器的分割函数（`SplitSeq`、`SplitAfterSeq`、`FieldsSeq`、`Lines`，Go 1.24 起），逐个产出元素而不构造整个切片。完整清单和示例见 `20-字符串与字节.md` 的“迭代器版分割 API（Go 1.24）”一节。

## 收集与展开：Collect、AppendSeq、Insert

`Collect` 是最常用的"迭代器 → 切片"转换：

```go
seq := slices.Values([]int{1, 2, 3})
result := slices.Collect(seq)

fmt.Println(result) // [1 2 3]
```

`AppendSeq` 则把迭代器中的元素追加到已有切片（Go 1.23 起），可以复用切片的容量：

```go
s := []int{1, 2}
seq := slices.Values([]int{3, 4})

s = slices.AppendSeq(s, seq)
fmt.Println(s) // [1 2 3 4]
```

`maps.Collect` 把键值对迭代器收成新的 map，`maps.Insert` 把迭代器插进已有 map（两者都是 Go 1.23 起，且 `Insert` 会覆盖同名 key）：

```go
m := maps.Collect(maps.All(map[string]int{"a": 1, "b": 2}))
fmt.Println(m) // map[a:1 b:2]

dst := map[string]int{}
maps.Insert(dst, maps.All(map[string]int{"a": 1}))
fmt.Println(dst) // map[a:1]
```

需要**稳定顺序**时，先收集再排序，不要指望迭代器的顺序（`slices.Collect`、`slices.Sort` 属于 `slices` 包，见 `15-slices.md`）：

```go
keys := slices.Collect(maps.Keys(m))
slices.Sort(keys)

for _, k := range keys {
    fmt.Println(k, m[k])
}
```

## 空迭代器与 nil 迭代器

"没有元素"和"迭代器本身是 nil"是两回事，后者会 panic：

```go
var seq iter.Seq[int] // nil

// slices.Collect(seq) // panic: invalid memory address or nil pointer dereference
```

所以需要区分这两种情况，接收迭代器的函数要先判 nil。

至于"空迭代器"经过标准库函数之后得到的容器是 nil 还是非 nil 空值，规则不统一（`slices.Collect` 给 nil、`slices.Values` 之后 `Repeat` 给非 nil 等），完整对照表见 `15-slices.md` 的"nil 与空切片"一节。

## 什么时候用迭代器

- **只遍历一次、可能提前结束**：用迭代器，省掉中间切片和它的分配。日志逐行、配置逐项、大文件切分都属于这一类。
- **需要随机访问、`len`、多次遍历，或者要把结果传给别人保存**：收集成切片（`slices.Collect`）。
- **给自定义容器写遍历入口**：返回 `iter.Seq` 比返回切片灵活，比实现 `Len`/`At` 风格的下标接口更符合 Go 的遍历习惯；标准库的 `go fix` 也带了 `stditerators` 重写器专门做这种迁移。
- **不要在热点路径上为了"看起来现代"而包一层迭代器**：多一层闭包调用就有开销，先测量再决定。
