# 07 切片

> Go 版本：>= 1.27.1  
> 相关标准库：slices、encoding/json

## 切片是什么

切片是对底层数组中一段连续元素的引用。它本身不保存元素，而是保存一个指向底层数组的指针、长度和容量——这三样合起来叫**切片头**（descriptor）：

```text
s := []int{10, 20, 30, 40}

  切片头 s                      底层数组
  ┌──────────────┐
  │ 指针 ────────┼──────▶  ┌────┬────┬────┬────┐
  │ len = 4      │         │ 10 │ 20 │ 30 │ 40 │
  │ cap = 4      │         └────┴────┴────┴────┘
  └──────────────┘           0    1    2    3
```

改元素改的是底层数组，所以**两个切片看到同一块数组时，一个动另一个也跟着动**（后面"底层数组共享"一节讲的就是这件事）。

**这是最容易带错直觉的一处**：写过 Python 或 JavaScript 的话，`s[1:3]` 给人的印象是"切出一份新的小列表"，Go 里恰恰相反——`s[1:3]` 不复制任何元素，只是在同一段数组上换了起点和长度。真正复制要显式用 `copy`、`slices.Clone` 或 `append`。

```go
a := []int{1, 2, 3, 4}
b := a[1:3] // 同一段数组上的另一个视图，不是副本

b[0] = 99

fmt.Println(a)     // [1 99 3 4] —— 原切片跟着变了
fmt.Println(len(b)) // 2 —— 视图自己的长度
fmt.Println(cap(b)) // 3 —— 从起点到数组末尾
```

声明一个切片而不初始化时，它是一个长度和容量都为 0 的 `nil`：

```go
var s []int
```

## 创建切片：字面量、`make`，零值也能直接用

字面量方式：

```go
s1 := []int{1, 2, 3}
```

使用 `make` 创建指定长度和容量：

```go
s2 := make([]int, 3)    // len=3 cap=3
s3 := make([]int, 0, 5) // len=0 cap=5
```

`make([]T, len)` 会把元素初始化为零值。`make([]T, len, cap)` 中容量可以大于长度，但容量不能小于长度。

### 零值与 nil 切片

切片的零值是 `nil`。`nil` 切片可以直接使用 `len`、`cap` 和 `range`，也可以直接 append：

```go
var s []int

fmt.Println(len(s)) // 0
fmt.Println(cap(s)) // 0

s = append(s, 1)
fmt.Println(s) // [1]
```

### 读取与修改

用下标访问和修改元素：

```go
s := []int{10, 20, 30}

fmt.Println(s[0]) // 10 —— 读取
s[1] = 99         // 修改
fmt.Println(s)    // [10 99 30]
```

## 切片表达式：左闭右开，容量也跟着切

基本形式：

```go
s[low:high]
```

包含 `low`，不包含 `high`。

```go
s := []int{0, 1, 2, 3, 4}

fmt.Println(s[1:3]) // [1 2]
fmt.Println(s[:2])  // [0 1]
fmt.Println(s[3:])  // [3 4]
fmt.Println(s[:])   // [0 1 2 3 4]
```

完整切片表达式还可以限制容量：

```go
s := []int{0, 1, 2, 3, 4}
t := s[1:3:3]

fmt.Println(len(t)) // 2
fmt.Println(cap(t)) // 2
```

容量被限制后，对 `t` 执行 `append` 会分配新数组，不会覆盖 `s` 后面的元素。

## len 和 cap：能看几个，还能长到哪

`len` 表示当前切片可见的元素个数，`cap` 表示从切片起始位置到底层数组末尾可以容纳的元素个数。

```go
s := make([]int, 2, 5)

fmt.Println(len(s)) // 2
fmt.Println(cap(s)) // 5
```

对切片继续切片时，长度和容量会变化：

```go
s := []int{0, 1, 2, 3, 4}
t := s[1:3]

fmt.Println(len(t)) // 2
fmt.Println(cap(t)) // 4
```

## 遍历：拿到的是副本，想改就得用下标

使用 `range` 遍历切片：

```go
s := []int{10, 20, 30}

for i, v := range s {
    fmt.Println(i, v) // 0 10 / 1 20 / 2 30
}
```

`v` 是元素的副本，修改 `v` 不会改变切片中的元素：

```go
for _, v := range s {
    v *= 2
}

fmt.Println(s) // [10 20 30]
```

需要修改元素时使用索引：

```go
for i := range s {
    s[i] *= 2
}

fmt.Println(s) // [20 40 60]
```

遍历只能看，不能改元素；真正常用的操作是往末尾追加，而它就带着下面这套"共享数组"的规则。

## append：必须把返回值赋回去

### 基本用法：追一个、追多个、追整个切片

`append` 用于在切片末尾追加元素，并返回新的切片。通常需要把返回值重新赋给原变量：

```go
s := []int{1, 2}

s = append(s, 3)
s = append(s, 4, 5)

fmt.Println(s) // [1 2 3 4 5]
```

也可以追加另一个切片：

```go
s := []int{1, 2}
t := []int{3, 4}

s = append(s, t...)
fmt.Println(s) // [1 2 3 4]
```

`append` 也可以在头部插入。方式 A 最直观，方式 B 省一次分配：

```go
// 方式 A：新建切片 + 展开
s := []int{2, 3, 4}
s = append([]int{1}, s...)
fmt.Println(s) // [1 2 3 4]

// 方式 B：原地（append 零值 + copy 后移 + 赋值）
s = append(s, 0)    // 先扩容一位，尾部补 0
copy(s[1:], s)      // 整体后移一位（copy 处理重叠，等价于 memmove）
s[0] = 0
fmt.Println(s)      // [0 1 2 3 4]
```

### 容量增长：为什么不是每次加 1

如果容量足够，`append` 会直接写入底层数组；如果容量不足，会分配新的底层数组并复制原有元素——**换数组这件事，就是"追加之后数据怎么跑到别处去了"的根源**：

```text
s := make([]int, 3, 3)   // cap 已经用满
s = append(s, 4)         // 容量不够，append 会：分配更大的数组 → 复制原元素 → 让切片头指向新数组

  追加前： s ──▶ [1 2 3]              cap=3，没有空位
  追加后： s ──▶ [1 2 3 4 _ _]        cap=6，旧数组 [1 2 3] 再没人指向它
```

`append` 的容量增长是几何式的：小切片大致翻倍，切片变大后增长比例会下降到 1.25 倍左右。因此连续 `append` 的均摊代价是 O(1)。

**换数组这件事有个直接后果**：如果别的地方还留着扩容前的切片（或从它切出来的子切片），那些视图仍指向**旧数组**，看不到你后来追加的内容。

```go
a := make([]int, 3, 3) // len=3 cap=3
copy(a, []int{1, 2, 3})
old := a[:2] // 扩容前的视图

a = append(a, 4) // 容量不够，换了一块新数组

a[0] = 99

fmt.Println(a)   // [99 2 3 4] —— 新数组上的改动
fmt.Println(old) // [1 2] —— 还停在旧数组上，看不到 99
```

判断"要不要担心换数组"，看 `cap` 就够了：`len(s) < cap(s)` 时 `append` 原地写，共享数组的视图会看到改动；`len(s) == cap(s)` 时一定会换数组，旧视图就此和新的 `s` 分家。

```go
var s []int

prev := cap(s)
for i := 0; i < 40; i++ {
    s = append(s, i)
    if cap(s) != prev {
        fmt.Print(cap(s), " ") // 4 8 16 32 64
        prev = cap(s)
    }
}
```

注意上面两个序列的**第一个**值（`[]int` 的 4、`[]byte` 的 32）不是增长策略算出来的：容量不够时 `append` 会先试一块**定长栈缓冲**，这一步的台阶按 `K = 32 / sizeof(元素)` 定（`[]int` 得 4、`[]byte` 得 32），装不下才转交运行时的增长策略去找新数组，所以第一次"扩容"之前容量就已经是这个数。`[]byte` 从 `nil` 开始 append 时首值正好是 32，就是这个台阶。

> **首值是实现细节，不要依赖它。** 那个 32 字节来自 `cmd/compile` 与运行时的配合（编译器内部阈值 `-d=variablemakethreshold`，默认 32），**不是语言规范**：换编译器（如 gccgo）、换 Go 版本，或者改了这个阈值，首值都会变；`-gcflags=-N` 关掉优化后台阶也不同。要确定的容量就用 `slices.Grow` 或 `make([]T, 0, n)`——显式给出的容量至少是你要的那个数，不用猜首值（见下面"提前预留容量"）。除首值以外的台阶才由运行时的增长策略给出。

元素越大、切片越长，增长比例越小。换 `[]byte` 追加 2000 次，容量序列是：

```go
var b []byte

prev := cap(b)
for i := 0; i < 2000; i++ {
    b = append(b, 0)
    if cap(b) != prev {
        fmt.Print(cap(b), " ") // 32 64 128 256 512 896 1408 2048
        prev = cap(b)
    }
}
```

### 提前预留容量

如果事先知道最终长度，可以在追加之前一次性把容量准备好，避免多次分配和复制：用标准库的 `slices.Grow`（Go 1.21 起）或者手写 `make([]T, 0, n)`。

```go
s := make([]int, 0, 1000) // 直接给出容量
fmt.Println(len(s), cap(s)) // 0 1000

t := slices.Grow([]int(nil), 1000) // 或者用 slices.Grow
fmt.Println(len(t), cap(t)) // 0 1024 —— 容量按运行时策略向上取整
```

`Grow` 只保证容量、不改变长度；它和 `make([]T, 0, n)` 的区别是容量可能比你要求的大一些。`slices.Grow` 的更多细节见 `15-slices.md`。

## append 与重叠：什么时候会改到别人的数据

### 追加自己：`s = append(s, s...)` 为什么安全

`s = append(s, s...)` 用来把切片复制一份接在自己后面，结果是正确的：

```go
s := []int{1, 2, 3}
s = append(s, s...)

fmt.Println(s) // [1 2 3 1 2 3]
```

这是可行的，因为 `append` 内部对元素做的是 `memmove` 式复制，源和目标重叠也不会读到被覆盖到一半的数据。容量足够时也成立：

```go
s := make([]int, 3, 8)
copy(s, []int{1, 2, 3})

s = append(s, s...)
fmt.Println(s) // [1 2 3 1 2 3]
```

### 源和目标重叠：真正会出错的那种情况

真正会出问题的是**共享底层数组**。当目标和源落在同一段数组上、且目标区间覆盖了源区间时，`append` 会把你还在使用的那个切片改掉：

```go
a := []int{1, 2, 3, 4, 5}
src := a[3:5] // [4 5]

b := append(a[:2], src...)

fmt.Println(b)   // [1 2 4 5]
fmt.Println(a)   // [1 2 4 5 5]
fmt.Println(src) // [5 5]，src 自己被 append 覆盖了
```

`append` 的写入目标 `a[2:4]` 与 `src`（即 `a[3:5]`）重叠，写完 `a[3] = 5` 之后，`src` 看到的就不再是原来的 `[4 5]`。

安全做法是先克隆，让追加的值来自快照：

```go
a := []int{1, 2, 3, 4, 5}
src2 := a[3:5] // [4 5]

c := append(a[:2], slices.Clone(src2)...)

fmt.Println(c)    // [1 2 4 5]
fmt.Println(src2) // [5 5]
```

注意 `slices.Clone` 只保证**被追加的值**是快照，它不能阻止 `append` 往共享数组里写：`src2` 作为同一段数组的另一个视图，仍然会被覆盖。如果其他视图也必须保持不变，就要把结果构造在新切片里：

```go
a := []int{1, 2, 3, 4, 5}
src := a[3:5]

out := append(slices.Clone(a[:2]), src...)

fmt.Println(out) // [1 2 4 5]
fmt.Println(a)   // [1 2 3 4 5]，原切片完全没动
```

结论：`append` 的复制本身不会读错数据，`s = append(s, s...)` 是安全的；需要克隆的场景是“源和目标共享同一段底层数组”——尤其当别的切片还在使用那段数组时。

## 底层数组共享：改一个视图，另一个也会变

上一节讨论了 `append` 在共享数组上的行为，本节进一步展示共享底层数组的基本机制。

多个切片可以共享同一个底层数组：

```go
a := []int{1, 2, 3, 4}
b := a[1:3]

b[0] = 99

fmt.Println(a) // [1 99 3 4]
fmt.Println(b) // [99 3]
```

修改 `b` 中的元素会影响 `a`，因为它们指向同一个底层数组。

`append` 也可能影响共享底层数组的其他切片：

```go
a := []int{1, 2, 3, 4}
b := a[:2]

c := append(b, 99)

fmt.Println(a) // [1 2 99 4]
fmt.Println(c) // [1 2 99]
```

这里 `b` 的容量是 4，`append` 没有扩容，而是直接修改了 `a` 的第三个元素。如果容量不足，`append` 会分配新数组，就不会出现这种覆盖。

`15-slices.md` 里的 `Delete`、`Insert`、`Replace`、`Compact`、`Reverse` 和排序系列同样是在这段共享数组上就地改，哪些函数属于这一类、以及它们置零尾部的细节都写在那篇。

## copy：在已有数组上搬数据

### 重叠复制：像 `memmove` 一样安全

`copy` 把源切片中的元素复制到目标切片：

```go
src := []int{1, 2, 3}
dst := make([]int, len(src))

n := copy(dst, src)

fmt.Println(n)   // 3
fmt.Println(dst) // [1 2 3]
```

`copy` 复制的元素个数是 `min(len(dst), len(src))`。它不会改变目标切片的长度。

`copy` 的行为和 C 的 `memmove` 一样：源和目标即使在同一段底层数组上重叠，也能得到正确结果，不会出现“边读边写把数据踩坏”的情况。

```go
s := []int{1, 2, 3, 4, 5}

copy(s[1:], s[:4])
fmt.Println(s) // [1 1 2 3 4]，而不是 [1 1 1 1 1]
```

```go
s := []int{1, 2, 3, 4, 5}

copy(s[:4], s[1:])
fmt.Println(s) // [2 3 4 5 5]
```

`copy` 的核心价值是**在已有底层数组上做内存级复制**，不改变目标切片的长度。删除元素用 `copy` + 截断是它的派生用法，详见“删除：尾巴上会残留一份副本”一节。

## 删除：尾巴上会残留一份副本

删除是 `append` 的逆向操作：把 `i` 之后的元素整体前移一位，再把长度减一。写法短到只有一行：

```go
s := []int{1, 2, 3, 4, 5}
i := 2

s = append(s[:i], s[i+1:]...)
fmt.Println(s) // [1 2 4 5]
```

上面这行本质上就是 `copy(s[i:], s[i+1:])` 再加上截断，两者等价：

```go
s := []int{1, 2, 3, 4, 5}
i := 2

n := copy(s[i:], s[i+1:])
fmt.Println(n, s) // 2 [1 2 4 5 5]

s = s[:len(s)-1]
fmt.Println(s) // [1 2 4 5]
```

两种写法都不会缩短底层数组：数组末尾会残留最后一个元素的副本（`5`），只是被新长度遮住了。需要真正清掉尾部时，可以用 `clear(s[len(s):cap(s)])` 或 `slices.Delete`（它会把尾部置零，见 `15-slices.md`）。

头部删除（`s = s[1:]`）最简单，但底层数组没释放，大数据时注意内存。想释放底层数组引用：

```go
copy(s, s[1:])    // 整体前移
s = s[:len(s)-1]  // 截掉最后一位
```

## nil 切片与空切片：平时一样，编码 JSON 时不一样

`nil` 切片和空切片长度都是 0，但它们的值不同：

```go
var a []int
b := []int{}

fmt.Println(a == nil) // true
fmt.Println(b == nil) // false
fmt.Println(len(a), len(b)) // 0 0
```

两者都可以 append、range 和传递。需要区分“尚未初始化”和“已初始化为空”时，再使用 `nil` 判断。

Go 里切片的零值就是 `nil`，所以 `var s []int` 本身就是合法且惯用的“空切片”，通常不需要写成 `[]int{}`。

只有编码成 JSON 时，两者的区别才会暴露出来：`encoding/json`（v1）把 nil 切片编码成 `null`，把非 nil 的空切片编码成 `[]`。

```go
var a []int  // nil
b := []int{} // 非 nil 空切片

data, _ := json.Marshal(a)
fmt.Println(string(data)) // null

data, _ = json.Marshal(b)
fmt.Println(string(data)) // []
```

反序列化时，JSON 里的 `null` 会让目标切片变回 `nil`，`[]` 得到一个非 nil 的空切片。如果下游接口期望一定收到 `[]`，要么显式初始化为 `[]int{}`，要么让 nil 也输出成 `[]`（`encoding/json/v2` 默认就把 nil 切片编码成 `[]`）。细节见 `26-JSON与序列化.md`。

## 原生增删改查速查

不引入 `slices` 包，只用 `append`、`copy`、下标和 `len`/`cap`：

```go
// 创建
s := []int{1, 2, 3}

// 读取/修改（按下标）
v := s[1]
s[0] = 99

// 追加
s = append(s, 4)

// 头部插入（见上文 append）
s = append([]int{0}, s...)

// 删除下标 i（见上文删除）
i := 2
s = append(s[:i], s[i+1:]...)

// 头部删除（见上文删除）
s = s[1:]

// 遍历（见上文遍历）
for i, x := range s {
    _ = i; _ = x
}
```

标准库的 `slices.Delete`、`slices.Insert`、`slices.Replace` 等函数是这些模式的封装，见 `15-slices.md`。

## 内存保留：一小段切片会拖住整个底层数组

上一节讨论了底层数组共享的机制，本节进一步说明子切片对底层数组生命周期的影响。

子切片会引用原底层数组。只要子切片还存在，底层数组就不会被回收。

```go
data := make([]byte, 1024)
header := data[:16]
```

如果 `header` 长期存在，整个 `data` 底层数组也会被保留。需要避免时可以复制出真正需要的数据：

```go
header := make([]byte, 16)
copy(header, data[:16])
```

`slices.Clone` 也可以用来生成独立副本，具体见 `15-slices.md`。

## clear：置零但不改长度

`clear`（Go 1.21 起的内建函数）可以把切片元素全部置为零值，但**不会改变长度**：

```go
s := []int{1, 2, 3}
clear(s)

fmt.Println(s)   // [0 0 0]
fmt.Println(len(s)) // 3
```

两个区别：

- `clear(s)` 和 `s = s[:0]` 不一样。前者长度不变、元素被置零；后者长度为 0，但底层数组里的元素还留着。要"真正清掉尾部"时用前者，要"逻辑上清空"时用后者。
- 它清的是**当前切片能看到的那个区间**（`[0, len(s))`），不会碰到容量里超出长度的部分。所以要清掉不再使用的尾部时，写法是 `clear(s[len(s):cap(s)])`，这正是"删除"节里配合使用的技巧。

`clear` 作用于 map 时的行为不同（删除所有 key），见 `08-map.md` 的"删除与清空"一节。

## 数组与切片的区别：长度算不算类型的一部分

数组长度是类型的一部分，切片长度不是。数组是值类型，赋值会复制整个数组；切片包含指向底层数组的引用，赋值只复制**切片头（descriptor）**。

"复制切片头"这件事有个直接后果：**函数里改切片元素会影响调用方，但要改切片本身（长度、容量）就得传 `*[]int` 或返回新切片**，例子见 `10-指针.md` 的"修改切片头本身"一节。

```go
var a [3]int = [3]int{1, 2, 3}
var s []int = []int{1, 2, 3}
```

更详细的数组内容见 `06-数组.md`。
