# 25 数学与随机数

> Go 版本：>= 1.27.1  
> 相关标准库：math、math/big、math/bits、math/rand/v2、crypto/rand

五个包对应"要什么精度、随机数要多随机"的五档：`math`（`float64` 的常规函数与常量）、`math/big`（超出机器精度、要求精确结果）、`math/bits`（按位运算与 128 位乘除）、`math/rand/v2`（可复现的伪随机，用于模拟、抽样、测试）、`crypto/rand`（不可预测的随机，用于密钥与令牌）。除随机数外都属"知道该用哪个包、剩下查文档"的类型，所以本篇只讲选包与几个容易用错的地方。

## math

`math` 包提供浮点数学函数和常量。

```go
// Pi：圆周率 π（常量，不是函数）
fmt.Println(math.Pi)          // 3.141592653589793
// Abs：绝对值
fmt.Println(math.Abs(-3.5))   // 3.5
// Sqrt：平方根
fmt.Println(math.Sqrt(16))    // 4
// Pow：x 的 y 次幂
fmt.Println(math.Pow(2, 10))  // 1024
// Floor：向下取整；Ceil：向上取整
fmt.Println(math.Floor(3.7))  // 3
fmt.Println(math.Ceil(3.2))   // 4
// Round：四舍五入到最近整数（.5 远离零）
fmt.Println(math.Round(3.5))  // 4
// Mod：浮点取余，结果符号跟随被除数；IEEE 取余是 math.Remainder
fmt.Println(math.Mod(5.5, 2)) // 1.5
```

比较浮点数时通常不能直接用 `==`，可以结合误差范围：

```go
const epsilon = 1e-9

func nearlyEqual(a, b float64) bool {
    return math.Abs(a-b) < epsilon
}
```

但**绝对误差只适合数值量级在 1 附近的场景**。数值很大时，`float64` 本身的相对精度约 1e-16，一点点相对误差就变成很大的绝对误差，此时绝对比较会把“已经是最近可表示值”的两个数判成不等：

```go
a := 1e18
b := a + 128 // 1e18 处 float64 的间隔（ULP）就是 128

fmt.Println(math.Abs(a-b) < 1e-9) // false —— 绝对误差认为它们不相等
```

换成**相对比较**（按两个数的量级缩放误差阈值）才正确；反过来数值极小时，绝对误差又会过于宽松（`1e-30` 和 `0` 会被判成相等）。把上面的 `nearlyEqual` 改成：

```go
func nearlyEqual(a, b float64) bool {
    diff := math.Abs(a - b)
    scale := math.Max(math.Abs(a), math.Abs(b))

    return diff <= 1e-9*scale
}
```

```go
fmt.Println(nearlyEqual(a, b)) // true
```

精确的小数运算（金额、比例）不要靠误差容忍度兜底，见下面的 `math/big`。

`math` 也提供特殊值和判断函数：

```go
// Inf：按符号构造正 / 负无穷（Inf(1) 是 +Inf）；NaN：构造"不是数字"
fmt.Println(math.Inf(1))              // +Inf
fmt.Println(math.NaN())               // NaN
// IsInf：判断是否无穷（第二个参数 0 表示不限符号）；IsNaN：判断是否 NaN
fmt.Println(math.IsInf(math.Inf(1), 0)) // true
fmt.Println(math.IsNaN(math.NaN()))   // true
```

整数运算通常不需要 `math`，直接使用运算符即可。

### 更多数值函数

```go
// Max / Min：两个浮点数里较大 / 较小的那个（整数取最值优先用内建 min/max）
fmt.Println(math.Max(3, 7))   // 7
fmt.Println(math.Min(3, 7))   // 3
// Trunc：向零取整（Floor 向下、Ceil 向上，见上文）
fmt.Println(math.Trunc(-3.7)) // -3
// Hypot：等价于 sqrt(p*p+q*q)，但避免中间结果溢出与下溢
fmt.Println(math.Hypot(3, 4)) // 5
// Log / Log2 / Log10：自然对数、以 2 为底、以 10 为底；Pow10：10 的 n 次幂
fmt.Println(math.Log(math.E)) // 1
fmt.Println(math.Log2(8))     // 3
fmt.Println(math.Log10(1000)) // 3
fmt.Println(math.Pow10(-3))   // 0.001
```

`math.Max`/`math.Min` 的参数和返回值都是 `float64`，并且沿用浮点语义：任一参数是 NaN 结果就是 NaN、`Max(+0, -0)` 是 `+0`。整数取最值用内置的 `max`/`min`（Go 1.21 起），保留原类型、也不用来回转换。

### 整数边界常量

`math` 里还有一组整数常量，省去自己写 `1<<63 - 1` 这类表达式：

```go
fmt.Println(math.MaxInt64) // 9223372036854775807
fmt.Println(math.MinInt64) // -9223372036854775808
fmt.Println(math.MaxInt32) // 2147483647
fmt.Println(math.MinInt32) // -2147483648
```

`MaxInt`/`MinInt` 随平台字长变化，其余成对的有 `MaxInt8`…`MaxInt64`、`MinInt8`…`MinInt64`。

## math/big 精确计算

`float64` 只有 53 位有效位，`int64` 会溢出，所以金额、大整数 ID、精确除法都不该用它们。`math/big` 提供任意精度算术：`big.Int`（整数）、`big.Rat`（有理数）、`big.Float`（浮点）。

`big.Int`：

```go
a := new(big.Int)
a.SetString("123456789012345678901234567890", 10) // 返回 (*Int, bool)
b := big.NewInt(1 << 62)

fmt.Println(new(big.Int).Add(a, b)) // 123456789016957364919661955794
fmt.Println(new(big.Int).Sub(a, b)) // 123456789007733992882807179986
fmt.Println(new(big.Int).Mul(a, a)) // 15241578753238836750495351562536198787501905199875019052100
fmt.Println(new(big.Int).Quo(a, b)) // 26770423771
fmt.Println(a.Cmp(b))               // 1 —— 约定同 cmp.Compare
fmt.Println(a.String())             // 十进制字符串
```

`SetString` 的第二个参数是进制（`0` 表示按 `0b`/`0o`/`0x` 前缀推断），并且要求**整个字符串**合法，失败时返回 `nil` 和 `false`：

```go
n, ok := new(big.Int).SetString("12x", 10)
fmt.Println(n, ok) // <nil> false
```

`big.Int` 和 `big.Rat` 都必须以指针使用：**不能用 `==` 比较两个 `big.Int`**（比的是内部字段而不是数值），要用 `Cmp`；复制值也不能浅拷贝，要用 `Set`。

指数运算用 `Exp`，结果写进接收者——`b.Exp(b, big.NewInt(100), nil)` 就是 `b = b¹⁰⁰`：

```go
b := big.NewInt(2)
b.Exp(b, big.NewInt(100), nil)

fmt.Println(b) // 1267650600228229401496703205376
```

运算是“目标指针 + 操作数”的形式（`z.Add(x, y)`），所以可以复用缓冲区、避免每次都分配：

```go
sum := new(big.Int)

sum.Add(a, b)                // sum = a + b
sum.Add(sum, big.NewInt(1))  // sum++
```

除法有两套语义：`Quo`/`QuoRem` 是**向零取整**（和 Go 的 `/` 一致），`Div`/`Mod`/`DivMod` 是**欧几里得除法**（余数非负，`Div` 的文档明确写了 “unlike Go”）。

```go
x, y := big.NewInt(-7), big.NewInt(2)

fmt.Println(new(big.Int).Quo(x, y)) // -3 —— 向零取整
fmt.Println(new(big.Int).Div(x, y)) // -4 —— 欧几里得除法
fmt.Println(new(big.Int).Mod(x, y)) // 1  —— 余数非负
```

Go 1.27 新增了带舍入模式的 `Divide` 和四个 `RoundingMode` 常量：

```go
x, y := big.NewInt(-7), big.NewInt(2)

// 第三个参数是余数的接收者；传 nil 表示不要余数，此时第二个返回值就是 nil
q, r := new(big.Int).Divide(x, y, new(big.Int), big.Trunc)
fmt.Println(q, r) // -3 -1

q, r = new(big.Int).Divide(x, y, new(big.Int), big.Floor)
fmt.Println(q, r) // -4 1

_, noRem := new(big.Int).Divide(x, y, nil, big.Trunc)
fmt.Println(noRem) // <nil> —— 不要余数时第二个返回值就是 nil
```

签名是 `func (z *Int) Divide(x, y, r *Int, mode RoundingMode) (*Int, *Int)`：满足 `q = f(x/y)`、`r = x - y*q`，接收者 `z` 接收商、参数 `r` 接收余数（传 `nil` 表示不要余数，此时第二个返回值就是 `nil`），`mode` 取值：

```text
 7/2:  Trunc=3   Floor=3   Ceil=4   Round=4
-7/2:  Trunc=-3  Floor=-4  Ceil=-3  Round=-4
 5/2:  Trunc=2   Floor=2   Ceil=3   Round=2   // Round 是“就近取偶”，2.5 取 2
```

四个常量分别对应 T 除法（`Trunc`，和 Go 的整数除法相同）、F 除法（`Floor`）、R 除法（`Round`，就近取偶）和上限除法（`Ceil`）。除数为 0 时 panic。

`big.Rat` 表示任意精度的分数：

```go
r := new(big.Rat).Add(big.NewRat(1, 3), big.NewRat(1, 6))

fmt.Println(r)                // 1/2
fmt.Println(r.RatString())    // 1/2
fmt.Println(r.FloatString(4)) // 0.5000 —— 只有转成小数时才引入精度
fmt.Println(r.IsInt())        // false —— 1/2 不是整数

f, exact := r.Float64()
fmt.Println(f, exact) // 0.5 true —— 第二个返回值表示转换是否精确

x, ok := new(big.Rat).SetString("0.1")
fmt.Println(x.RatString(), ok, x.IsInt()) // 1/10 true false
```

`big.Rat` 的加减乘除都不丢精度（分子分母都是 `big.Int`），只有显式 `Float64()`/`FloatString(prec)` 才引入误差。`new(big.Int)` 的零值就是 0、`new(big.Rat)` 的零值就是 0。

关于金额：更省事的做法是**用整数存最小单位**（分、厘），需要小数运算（汇率、税率、按比例分摊）时再引入 `big.Rat`。`float64` 连 `0.1` 都不能精确表示，累加会放大误差——字面量 `0.1` 在编译期是精确常量，精度是存进 `float64` 之后才丢的（见 `01-变量与基础类型.md` 的“浮点类型”一节）。

代价是 `math/big` 的每次运算都可能涉及堆分配，比原生类型慢得多，所以只在确实需要任意精度时才用。

## math/bits 位运算

什么时候会用到：写位图、布隆过滤器、权限位、哈希函数，或者要在协议里打包定长字段时。这些函数基本都编译成单条 CPU 指令（POPCNT、LZCNT、TZCNT、MULQ 等），比自己写循环快得多：

```go
// OnesCount：二进制里 1 的个数（popcount）
fmt.Println(bits.OnesCount(0b1011)) // 3
// Len：表示 x 至少需要几位，Len(0) 是 0
fmt.Println(bits.Len(8))            // 4
fmt.Println(bits.Len(0))            // 0
// LeadingZeros / TrailingZeros：最高位之前 / 最低位之后有几个 0
fmt.Println(bits.LeadingZeros(1))   // 63（64 位平台）
fmt.Println(bits.TrailingZeros(8))  // 3
```

按 `uint` 宽度定义的还有 `OnesCount8/16/32/64`、`Len8/16/32/64`、`LeadingZeros8/…`、`TrailingZeros8/…`；`LeadingZeros(0)`/`TrailingZeros(0)` 返回 `bits.UintSize`（0 按整字长处理）。

不带后缀的版本按平台字长（`uint`）计算，32 位和 64 位平台上结果不同；**需要跨平台一致时必须用带后缀的 `…64` 版本**。`bits.OnesCount64` 在支持的 CPU 上编译成一条 `POPCNTQ`（编译器会插入能力检查，不支持的平台退回纯 Go 实现），而自己写的 `for ; x != 0; x &= x - 1 { n++ }` 编译器不会识别成 popcount，仍然是一条逐位循环——可以用 `go build -gcflags=-S` 对比两者的汇编来确认（用法见 `00-工具链.md` 的"go build -gcflags"一节）。要做位运算先来这个包查一遍。

把容量向上取整到 2 的幂是 `Len` 的常见用法：

```go
n := 1000

p := 1 << bits.Len(uint(n-1))
fmt.Println(p) // 1024
```

判断一个数是不是 2 的幂可以看 `bits.OnesCount(x) == 1`。包里还有 `bits.Mul64`/`bits.Div64`（128 位乘除，返回高低两半）和 `bits.RotateLeft64`（循环移位），但那些属于位运算密集的场景，需要时查 `go doc math/bits` 即可。

## math/rand/v2

Go 1.22 起提供 `math/rand/v2`，新代码应优先使用它。

### 与 v1（`math/rand`）的关系

`math/rand` 并没有被废弃，存量代码里到处都是它，所以两件事要分清：

- **v1 仍然可用**，但新代码不该再选它。v2 是同一个团队基于新算法（PCG、ChaCha8）重写的版本，顺带修掉了 v1 的几处设计问题。
- **两者是不同的包，不能混用**：`rand.New(rand.NewPCG(1, 2))` 里的 `rand` 是 v2，而 v1 的 `*rand.Rand` 和 v2 的 `*rand.Rand` 是两个类型，传入对方期望的参数会直接编译失败。

看到旧代码时，按下表对照即可：

| 用途         | v1（`math/rand`）                                | v2（`math/rand/v2`）                                            |
| ------------ | ------------------------------------------------ | --------------------------------------------------------------- |
| 整数         | `rand.Intn(n)`                                   | `rand.IntN(n)`（**大写 N**）                                    |
| 指定宽度整数 | `rand.Int31()` / `Int63()` / `Int31n` / `Int63n` | `rand.Int32()` / `Int64()` / `Int32N` / `Int64N` / `UintN` 系列 |
| 浮点         | `rand.Float64()`                                 | `rand.Float64()`（同名）                                        |
| 种子         | `rand.Seed(x)`——**Go 1.24 起是空操作**           | 没有 `Seed`；用 `rand.New(rand.NewPCG(seed1, seed2))`           |
| 全局源       | 隐式、可被 `Seed` 影响                           | 不可播种；要可复现就自建 `*rand.Rand`                           |

两个最容易踩的点：

- **`math/rand.Seed` 在 Go 1.24 起是空操作（no-op）**，调用它不会报错、也不会有任何效果；那些靠 `rand.Seed(42)` 保证"每次跑出同一串数"的旧代码，升级后**会静默地不再可复现**。实测：

  ```go
  rand.Seed(1)
  a := rand.Intn(1000)
  rand.Seed(1)
  b := rand.Intn(1000)

  fmt.Println(a, b) // 例如 100 517 —— 两次不同，Seed 没起作用
  // 设 GODEBUG=randseednop=0 后才恢复旧行为（两次都是 81）
  ```

  现在的正确做法是自建来源（`rand.New(rand.NewPCG(...))`，见下文），而不是去调 `Seed`。同理，v1 的全局源从 Go 1.20 起会**自动随机播种**，所以"忘了播种"不再意味着每次都跑同一串数。

- `Intn` 与 `IntN` 只差一个字母大小写，跨版本复制代码时极易搞错；编译报错是好事，别用类型转换去"绕过"。

生成随机数：

```go
fmt.Println(rand.Int())     // 随机值，每次运行都不同；全局源不可播种
fmt.Println(rand.IntN(100)) // 同上，落在 [0, 100)
fmt.Println(rand.Float64()) // 同上，落在 [0.0, 1.0)
```

随机打乱：

```go
s := []int{1, 2, 3, 4, 5}
rand.Shuffle(len(s), func(i, j int) {
    s[i], s[j] = s[j], s[i]
})
```

生成排列：

```go
p := rand.Perm(5)
fmt.Println(p) // 是 0~4 的一个随机排列，顺序每次运行都不同
```

需要固定随机序列时，创建自己的随机源：

```go
source := rand.NewPCG(1, 2)
r := rand.New(source)

fmt.Println(r.IntN(100)) // 76 —— 同样的种子总是这个值，序列可复现
```

### 更多随机 API

`*rand.Rand` 上的 `IntN` 只能返回 `int`；**Go 1.27 新增了泛型版本 `N`**，可以指定任意整数类型：

```go
r := rand.New(rand.NewPCG(1, 2))

fmt.Println(r.N(100))         // 76（int，等价于 r.IntN(100)）
fmt.Println(r.N(uint8(10)))   // 6
fmt.Println(r.N(int64(1000))) // 784
```

签名是 `func (r *Rand) N[Int intType](n Int) Int`，区间同样是 `[0, n)`。

默认源上的其他常用函数：

```go
fmt.Printf("%T\n", rand.Uint64()) // uint64
fmt.Println(rand.NormFloat64())   // 服从标准正态分布
```

长尾分布（热点 key 的访问分布之类）用 `Zipf`，需要一个自己的 `*Rand`：

```go
z := rand.NewZipf(r, 1.5, 1, 100)

fmt.Println(z.Uint64()) // 落在 [0, 100]，越小的值概率越高
```

需要**可复现又更强**的随机源时用 `rand.ChaCha8`（ChaCha8 的密码学强度 PRNG，同一个 seed 产生同一序列，可用于需要确定性重放的模拟）：

```go
var seed [32]byte
c := rand.NewChaCha8(seed)

fmt.Println(c.Uint64()) // 12432809566553409497 —— 同一个 seed 总是这个值
```

`ChaCha8` 本身是密码学强度的，但 `math/rand/v2` 的定位仍是模拟与采样；密钥、token、验证码这类用途继续用 `crypto/rand`。

### 任意区间：标准库没有助手，得自己平移

标准库只给 `[0, n)` 一族（`IntN`/`Int32N`/`Int64N`/`UintN`…）和 `[0, 1)` 的 `Float64`/`Float32`，**没有 `[lo, hi)` 的助手函数**，任意区间都靠"取一个 `[0, 宽度)` 再平移"：

```go
r := rand.New(rand.NewPCG(1, 2))

lo, hi := 10, 20

v := lo + r.IntN(hi-lo) // [10, 20) —— 取不到 20
fmt.Println(v >= lo && v < hi) // true

w := lo + r.IntN(hi-lo+1) // [10, 20] —— 闭区间，能取到 20
fmt.Println(w >= lo && w <= hi) // true

n := -5 + r.IntN(11) // 负数区间一样：[-5, 5]
fmt.Println(n >= -5 && n <= 5) // true

f := 1.5 + r.Float64() // 浮点同理：[1.5, 2.5)，取不到 2.5
fmt.Println(f >= 1.5 && f < 2.5) // true
```

三条容易踩的：

- **`n <= 0` 会 panic**：半开区间下 `hi <= lo` 直接崩，闭区间下 `hi == lo` 是合法的（`IntN(1)` 恒为 0）。区间来自外部输入（配置、请求参数）时必须先校验。
- **别写成 `r.Int64() % n`**：取模有偏差，除非 `n` 正好整除源能取的值个数。`IntN` 内部用的是拒绝采样，这才是它比"自己取模"更该用的原因。
- **`hi - lo + 1` 会溢出**：`lo = math.MinInt`、`hi = math.MaxInt` 时 `hi - lo` 溢出成 `-1`、再加一得 `0`，于是 `IntN(0)` 直接 panic。极值范围改用 `Int64N`/`Uint64N`，或者分两段取。

要"固定小数位的区间"（金额、百分比），别硬凑浮点，用整数算完再除：

```go
r := rand.New(rand.NewPCG(1, 2))

hundredths := 100 + r.IntN(101) // 以"分"为单位：[100, 200]

fmt.Println(hundredths >= 100 && hundredths <= 200) // true
fmt.Printf("%.2f\n", float64(hundredths)/100)       // 形如 1.23，两位小数不会跑出 [1.00, 2.00]
```

## crypto/rand 安全随机数

只要随机值被用来防猜测（密钥、token、验证码、会话 ID、UUID），就必须用 `crypto/rand`，`math/rand/v2` 无论换什么源都不行（标准库的 UUID 生成见 `28-UUID.md`）：

```go
b := make([]byte, 16)

if _, err := rand.Read(b); err != nil { // 这里的 rand 是 crypto/rand
    fmt.Println(err)
    return
}

fmt.Printf("%x", b)
```

`crypto/rand.Read` 的文档明确写着它 _never returns an error_ 并且总是填满整个切片（真出错会直接终止程序），但保留 `if err != nil` 判断仍是通行写法。只需要一个随机字符串时用 `crypto/rand.Text()`，返回 RFC 4648 base32 字母表的文本、至少 128 位随机性，适合直接当 token。

要**区间**上的安全随机数用 `crypto/rand.Int(rand.Reader, big.NewInt(n))`：它同样给出 `[0, n)`（内部拒绝采样，无偏），别的区间一样自己平移——**不要**写成 `% n`，安全场景里取模偏差是可利用的。

## 选包清单

| 你要的                                     | 用哪个                  | 一句话理由                                                        |
| ------------------------------------------ | ----------------------- | ----------------------------------------------------------------- |
| ------------------------------------------ | --------------          | --------------------------------------------------------          |
| 三角函数、对数、取整、常量                 | `math`                  | `float64` 就够用时别上 `big`                                      |
| 结果不能有误差（金额、大整数、高精度小数） | `math/big`              | `Float64` 有精度损失，`big.Int`/`big.Rat` 没有                    |
| 按位运算、前导零、128 位乘除               | `math/bits`             | 手写循环不会被编译成 `POPCNTQ` 这类指令，这里会                   |
| 模拟、抽样、测试要可复现                   | `math/rand/v2`          | 固定种子即可重现；**不要**用它生成密钥或 token                    |
| 密钥、token、盐                            | `crypto/rand`           | 不可预测；`Read` 不会返回错误，`Text()` 直接给随机字符串          |
| 生成 `[lo, hi)` 上的随机数                 | `lo + rand.IntN(hi-lo)` | 标准库只有 `[0, n)`，区间要自己平移；安全场景用 `crypto/rand.Int` |

两条最容易踩的：`math/rand/v2` 没有 `Seed`（要固定种子得自建 `*rand.Rand`，见上文"math/rand/v2"一节）；`math/big` 的运算方法是**就地改写接收者**的指针语义——`z.Add(x, y)` 会把结果写进 `z` 并返回 `z`，所以别把同一个 `*big.Int` 当不可变值到处传。
