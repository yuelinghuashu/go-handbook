# 21 io 与流

> Go 版本：>= 1.27.1  
> 相关标准库：io、bufio、strings、bytes、os

`io.Reader` 和 `io.Writer` 是 Go 里最重要的两个抽象：它们描述的是**字节流**，与数据从哪里来、到哪里去无关——文件、网络连接、内存缓冲、压缩流、编码器都实现它们。正因为只依赖这两个接口，标准库的工具函数才能通用于所有这些场景。

本篇解决三件事：认识 `Reader`/`Writer` 这对接口、用 `io` 的工具函数搬运数据、用 `bufio` 做带缓冲和按分隔符的读写。

读这一篇要用到接口（`12-接口.md`，`Reader`/`Writer` 本身就是接口）；少数例子还要起 goroutine（`38-并发基础.md`），读到时会指出来。

本篇只讲**流**本身，示例统一用内存对象（`strings.NewReader`、`bytes.Buffer`、`io.Discard`）：它们的 `Read`/`Write` 不返回错误，所以示例里用 `_` 忽略 err。真实代码里 IO 错误必须处理，它总会长成 `if err != nil { return nil, fmt.Errorf("read config: %w", err) }` 这个样子——本篇“Scanner、Reader”两节的 `scanLines`/`readLines` 就是现成范例，完整写法见 `05-错误处理.md`；真实文件与网络流的操作分别在 `22-文件与目录操作.md`、`30-网络与HTTP.md`。

## io.Reader 与 io.Writer

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}
```

## io 常用函数

把全部内容读进来用 `io.ReadAll`；两个流对接用 `io.Copy`（它会优先使用 `WriterTo`/`ReaderFrom`，通常比手写 `Read`+`Write` 循环少一层缓冲）；只允许读一部分用 `io.LimitReader`；协议里"必须读满 N 字节"用 `io.ReadFull`。

### 读取全部内容

```go
data, _ := io.ReadAll(strings.NewReader("hello"))

fmt.Printf("%q\n", data) // "hello"
```

`io.ReadAll` 把**全部内容读进内存**，所以只适合小数据。真实文件上它的文件版是 `os.ReadFile`（一次调用搞定打开、读完、关闭，见 `22-文件与目录操作.md`）；反过来，**大小不可控时不要 `ReadAll`**（日志、上传、HTTP body）：改用下一节的 `io.Copy` 流式搬运。

### 复制数据

```go
var dst bytes.Buffer

n, _ := io.Copy(&dst, strings.NewReader("hello"))

fmt.Println(n, dst.String() == "hello") // 5 true
```

`io.Copy` 分块搬运，内存占用与数据量无关（两个 `*os.File` 之间还会走 `copy_file_range`/`sendfile` 这类零拷贝路径），所以**跨流搬运一律用它**：文件到文件、上传流写到磁盘、响应体转发给客户端，以及把不要的 body 抽干（`io.Copy(io.Discard, body)`）。

反过来，`io.Copy(&buf, src)` 是把整条流攒进 `bytes.Buffer`——**内存随数据量线性增长**，大文件会 OOM。

### 限制读取长度

```go
data, _ := io.ReadAll(io.LimitReader(strings.NewReader("hello world"), 5))

fmt.Printf("%q\n", data) // "hello"
```

### 精确读取固定长度

**进阶，业务代码很少直接用，可以先跳过**——二进制协议、自定义编解码器才会碰到。

`io.ReadAll` 读到 EOF 为止；协议解析这类场景需要“读满这么多字节”的语义：

```go
r := strings.NewReader("abcd")
buf := make([]byte, 4)

n, err := io.ReadFull(r, buf) // 必须读满 len(buf)
fmt.Println(n, err) // 4 <nil>
```

`io.ReadFull` 在还没读满就遇到 EOF 时返回 `io.ErrUnexpectedEOF`（不是 `io.EOF`）：

```go
buf := make([]byte, 100)
_, err := io.ReadFull(strings.NewReader("ab"), buf)

fmt.Println(err)                                 // unexpected EOF
fmt.Println(errors.Is(err, io.ErrUnexpectedEOF)) // true
```

`io.ReadAtLeast` 只要读够 `min` 字节就成功，可以少于 `len(buf)`；`min` 大于 buffer 长度时返回 `io.ErrShortBuffer`：

```go
r := strings.NewReader("abcd")
buf := make([]byte, 8)

n, err := io.ReadAtLeast(r, buf, 3)
fmt.Println(n, err) // 4 <nil> —— r 只有 4 个字节，够 min 就成功
```

`io.CopyN` 是“只复制前 n 字节”的 `io.Copy`：

```go
var dst bytes.Buffer

written, _ := io.CopyN(&dst, strings.NewReader("hello world"), 5)

fmt.Println(written, dst.String() == "hello") // 5 true

// 源不足 n 字节时写出的比 n 少，err 是 io.EOF；错误在这里是结果的一部分，直接看它
var short bytes.Buffer

written, err := io.CopyN(&short, strings.NewReader("ab"), 5)
fmt.Println(written, errors.Is(err, io.EOF)) // 2 true
```

## 写入与分流

`io.MultiWriter` 让一次写同时落到多个 Writer，返回值本身也是 `io.Writer`：

```go
var buf bytes.Buffer

writer := io.MultiWriter(&buf, os.Stdout)

// 一次写入同时落进 buf 和 os.Stdout；MultiWriter 自己不存错误，写失败只能当场处理
if _, err := fmt.Fprintln(writer, "hello"); err != nil {
    fmt.Printf("write greeting: %v\n", err)
    return
}

fmt.Println(buf.String() == "hello\n") // true
```

`os.Stdout` 是 `*os.File`，也是最常见的 `io.Writer` 之一。

### 边读边写

`io.TeeReader(src, w)` 把从 `src` 读到的每个字节顺手写给 `w`（名字来自 Unix 的 `tee`），返回的新 Reader 读到什么，`w` 就拿到什么：

```go
var logged bytes.Buffer

reader := io.TeeReader(strings.NewReader("hello"), &logged)

data, _ := io.ReadAll(reader)

fmt.Printf("%q %q\n", data, logged.String()) // "hello" "hello"
```

### 丢弃输出与往 Writer 写字符串

`io.Discard` 是一个所有 `Write` 都成功、但什么都不做的 `io.Writer`，适合占位或跑基准：

```go
var w io.Writer = io.Discard

n, err := io.WriteString(w, "hello")
fmt.Println(n, err) // 5 <nil>
```

`io.WriteString(w, s)` 把字符串写进 `io.Writer`：如果 `w` 实现了 `io.StringWriter`（`WriteString` 方法），会直接调用它，省掉 `[]byte(s)` 的转换和分配。

往任意 Writer 写文本还可以用 `fmt.Fprintf`（`Fprint*` 家族与格式动词见 `01-变量与基础类型.md` 的“输出与格式化、常用格式动词”两节）：

```go
var buf bytes.Buffer

fmt.Fprintf(&buf, "name=%s", "gopher")

fmt.Println(buf.String() == "name=gopher") // true
```

## 包装与拼接 Reader

`io.NopCloser` 给任意 `io.Reader` 加一个空实现的 `Close`，用来满足接受 `io.ReadCloser` 的接口：

```go
rc := io.NopCloser(strings.NewReader("data"))
defer rc.Close()
```

`io.MultiReader` 把多个 Reader 逻辑拼接成一个，依次读完后返回 `io.EOF`：

```go
// MultiReader 把多个 Reader 按顺序拼成一个；NewReader 把字符串包成 Reader
data, _ := io.ReadAll(io.MultiReader(
    strings.NewReader("a"),
    strings.NewReader("b"),
    strings.NewReader("c"),
))

fmt.Printf("%q\n", data) // "abc"
```

### 管道

`io.Pipe` 提供一对同步的内存管道，把“写”和“读”两部分代码连起来。**业务代码基本用不到，写给中间件、代理、编解码器的作者看**，可以跳到下一节：

```go
pr, pw := io.Pipe()

go func() {
    if _, err := fmt.Fprintln(pw, "hello"); err != nil {
        // 写端出错要用 CloseWithError 交给读端：只 Close 的话，读端只看到“正常结束”
        pw.CloseWithError(fmt.Errorf("write greeting: %w", err))
        return
    }

    pw.Close()
}()

data, err := io.ReadAll(pr)
if err != nil {
    fmt.Printf("read pipe: %v\n", err)
    return
}

fmt.Printf("%q\n", data) // "hello\n" —— Fprintln 补了换行，读端拿到的是完整的这一行
```

要点：`io.Pipe` **没有内部缓冲，是同步的**——一次 `Write` 会阻塞到有 `Read` 把数据消费掉。所以必须像上面那样把写端放进单独的 goroutine（`38-并发基础.md` 的“goroutine：启动之后没人管”一节），否则单 goroutine 里先写后读会直接死锁。写端结束时用 `Close`（或 `CloseWithError` 传递错误）通知读端 EOF——写端的失败只写进日志是不会让读端知道的，`ReadAll` 那边会把它当成正常的 `nil`。

### EOF

`io.EOF` 表示没有更多数据可读。使用 `io.ReadAll` 等高层函数时，通常不需要手动判断它——它们把 `io.EOF` 当作“正常读完”，返回 `nil`；只有自己写 `Read` 循环时才会直接看到它：

```go
r := strings.NewReader("") // 里面没有数据
buf := make([]byte, 4)

_, err := r.Read(buf)

fmt.Println(errors.Is(err, io.EOF)) // true
```

## bufio

`bufio` 在底层 Reader 和 Writer 之上增加缓冲。它包装的是 `io.Reader`/`io.Writer`，所以文件、网络连接、内存缓冲一视同仁。

### Scanner

`Scanner` 按行（默认按 `\n`）切分输入，是逐行处理文本最常用的方式：

```go
func scanLines(r io.Reader) ([]string, error) {
    scanner := bufio.NewScanner(r)

    var lines []string
    for scanner.Scan() {
        lines = append(lines, scanner.Text())
    }

    if err := scanner.Err(); err != nil {
        return nil, fmt.Errorf("scan input: %w", err)
    }
    return lines, nil
}

lines, _ := scanLines(strings.NewReader("first\nsecond\n"))

fmt.Printf("%q\n", lines) // ["first" "second"]
```

把 `strings.NewReader(...)` 换成 `os.Open(...)` 的返回值就是逐行读文件，换成 `net.Conn` 就是逐行读网络——`Scanner` 只认 `io.Reader`。

### 从 stdin 读一行

标准库没有类似 Python `input()` 的函数。`fmt.Scanln` 按空白分词，`"Tom Jerry"` 会被拆成两个 token，不是读整行；从标准输入读一整行最自然的方式是复用同一个 `Scanner`：

```go
scanner := bufio.NewScanner(os.Stdin)

fmt.Print("name: ")
if scanner.Scan() {
    fmt.Println("hello,", scanner.Text())
if err != nil {
    fmt.Println(err)
    return
}
// Ctrl+D（Unix）或 Ctrl+Z（Windows）触发 EOF，Scan() 返回 false、Err() 为 nil
```

同一个 `Scanner` 可以反复调用 `Scan()`，每次读一行，不要在循环里每次 `bufio.NewReader(os.Stdin)`，`bufio.Reader` 会预读缓冲，新建实例会丢掉上一次多读的数据。

### Scanner 的 token 上限

上面例子最后那段 `scanner.Err()` 检查**不能省**，原因就在这里：`Scanner` 默认能读的单个 token（默认按行切分，就是一行）上限是 `bufio.MaxScanTokenSize`，值为 `64 * 1024`（64 KiB）——文档还注明实际可用上限可能略小，因为缓冲区还得放下换行符之类的字节。一旦某行超过上限，`Scan()` 直接返回 `false` 并永久停止，错误通过 `Err()` 返回 `bufio.ErrTooLong`：

```go
long := strings.Repeat("x", 70*1024) + "\n"

scanner := bufio.NewScanner(strings.NewReader(long))
fmt.Println(scanner.Scan()) // false
fmt.Println(scanner.Err())  // bufio.Scanner: token too long
```

日志或 JSONL 里出现一条超长记录，循环安静地提前结束，剩下的数据全部丢失；而如果没检查 `Err()`，程序看起来就像“文件读完了”。所以要么检查错误，要么显式放大上限：

```go
long := strings.Repeat("x", 70*1024) + "\n" // 70 KiB 的一行，默认上限读不了

scanner := bufio.NewScanner(strings.NewReader(long))
scanner.Buffer(make([]byte, 0, 1024*1024), 1024*1024) // 初始 1 MiB，上限 1 MiB

fmt.Println(scanner.Scan(), len(scanner.Text())) // true 71680

fmt.Println(scanner.Err()) // <nil> —— 放宽上限之后这一行读得下来
```

`Scanner.Buffer(buf, max)` 的语义：

- 最大 token 大小是 `max` 与 `cap(buf)` 中的**较大者**：`max` 只在你给的缓冲区更小时才起作用。
- `max <= cap(buf)` 时完全复用你给的缓冲区，扫描过程中不再分配。
- 在 `Scan` 开始之后调用会 panic。

单行长度确实不可控时，也可以改用 `bufio.Reader` + `ReadString('\n')`，它没有 token 上限。两种方案怎么选，见末尾的"选择与坑"。

### Scanner 的切分函数

**进阶，可以跳过**——需要按词/按 rune/按字节切分时才看。

默认切分函数是 `bufio.ScanLines`（按行切、去掉行尾的 `\r?\n`）。`bufio` 还内置了另外三个：

- `bufio.ScanWords`：空白分隔的词（按 `unicode.IsSpace`），不会返回空 token。
- `bufio.ScanRunes`：每次一个 rune。
- `bufio.ScanBytes`：每次一个字节。

切分函数只改切分粒度，循环体与上面的 `scanLines` 完全一样，这里只留差异：

```go
scanner := bufio.NewScanner(strings.NewReader("go   is\tfast"))
scanner.Split(bufio.ScanWords)

var words []string
for scanner.Scan() {
    words = append(words, scanner.Text())
}

fmt.Printf("%q\n", words) // ["go" "is" "fast"]
```

`ScanRunes` 遇到非法 UTF-8 字节会给出 `"\xef\xbf\xbd"`（U+FFFD），行为与 `range` 字符串一致，因此无法区分“原本就是替换字符”和“编码错误”。

`Split` 必须在扫描开始前调用，扫描中调用会 panic。需要 `[]byte` 时用 `scanner.Bytes()` 代替 `scanner.Text()`，它不做分配：

```go
scanner := bufio.NewScanner(strings.NewReader("go is fast"))
scanner.Split(bufio.ScanWords)

var aliased, copied [][]byte
for scanner.Scan() {
    token := scanner.Bytes() // 底层数组会被下一次 Scan 覆盖

    aliased = append(aliased, token)                       // 错：三次都指向同一块内存
    copied = append(copied, append([]byte(nil), token...)) // 对：要保留就自己复制
}

fmt.Println(scanner.Err()) // <nil>

fmt.Printf("%q %q %q\n", aliased[0], aliased[2], copied[0]) // "fast" "fast" "go"
```

`aliased[0]` 打出来已经是 `"fast"`：三次 `Bytes()` 返回的是同一块缓冲区，这正是它“不做分配”的代价。

### Reader

```go
func readLines(r io.Reader) ([]string, error) {
    reader := bufio.NewReader(r)

    var lines []string
    for {
        line, err := reader.ReadString('\n')
        if line != "" {
            lines = append(lines, strings.TrimSuffix(line, "\n"))
        }
        if err != nil {
            if errors.Is(err, io.EOF) {
                return lines, nil
            }
            return nil, fmt.Errorf("read line: %w", err) // 真正的读取错误
        }
    }
}

// 最后一行没有 \n，照样要读出来
lines, _ := readLines(strings.NewReader("first\nsecond"))

fmt.Printf("%q\n", lines) // ["first" "second"]
```

`ReadString` 遇到错误时会把**已经读到的数据连同错误一起返回**，只判断 `err != nil` 就返回的写法会丢掉最后一行，这正是上面 Scanner 一节警告过的“安静丢数据”。所以顺序是：先处理 `line`，再看 `err`；`err` 是 `io.EOF` 就走正常收尾，其余错误才上抛。上面 `if line != ""` 是躲开“读完最后一行后又读一次、拿到空串 + `io.EOF`”的那一轮。

### Writer

```go
var buf bytes.Buffer

writer := bufio.NewWriter(&buf)
fmt.Fprintln(writer, "hello")

fmt.Println(buf.Len()) // 0：还在缓冲区里，底层一个字节都没拿到

if err := writer.Flush(); err != nil {
    fmt.Printf("flush buffer: %v\n", err)
    return
}

fmt.Println(buf.String() == "hello\n") // true
```

`bufio.Writer` 需要调用 `Flush`，否则缓冲中的数据可能不会写入底层。写调用的错误它会**存起来**，最后由 `Flush` 一起返回，所以这里的 `Flush` 检查把前面 `Fprintln` 的失败也一并带出来了。

## 选择与坑

判据集中在这里，每条在上文都有出处（只做索引，不重复展开）：

- **大小可控用 `io.ReadAll`，不可控用 `io.Copy`**：日志、上传、HTTP body 走后者；`io.Copy(&buf, src)` 会 OOM（见“读取全部内容、复制数据”两节）。
- **逐行读用 `bufio.Scanner`，但记住单行 64 KiB 上限**：超长行要么 `scanner.Buffer(...)` 放大，要么换 `bufio.Reader.ReadString('\n')`（见“Scanner 的 token 上限、Reader”两节）。
- **`Scanner` 循环后必须查 `Err()`**，否则超长行静默截断（见“Scanner 的 token 上限”一节）。
- **写缓冲必须 `Flush`**：`Write` 返回 `nil` 不代表写成功，错误最后由 `Flush`（或 `Close`）抛出（见“Writer”一节）。
- **写过的句柄 `Close` 要查错误**，只读句柄才可以 `defer f.Close()`（见 `22-文件与目录操作.md`）。
- **`scanner.Bytes()` 的结果会被下次 `Scan` 覆盖**，要保留就自己复制（见“Scanner 的切分函数”一节）。
