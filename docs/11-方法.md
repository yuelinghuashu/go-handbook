# 11 方法

> Go 版本：>= 1.27.1  
> 相关标准库：time

方法是给**类型**绑定行为的语法，读之前先熟悉结构体（`09-struct.md`）——下面第一个例子就拿它当接收者。

## 方法声明

方法是带接收者的函数。接收者写在 `func` 和函数名之间。

```go
type User struct {
    Name string
    Age  int
}

func (u User) Hello() string {
    return "hello, " + u.Name
}
```

调用方法：

```go
u := User{Name: "Tom", Age: 18}

fmt.Println(u.Hello()) // hello, Tom
```

## 值接收者

值接收者会复制接收者：

```go
type User struct {
    Name string
    Age  int
}

func (u User) Birthday() {
    u.Age++
}

u := User{Name: "Tom", Age: 18}
u.Birthday()

fmt.Println(u.Age) // 18
```

修改 `u` 的副本不会影响原变量。

值接收者适合：

- 接收者较小
- 不需要修改原值
- 类型本身是不可变值

## 指针接收者

指针接收者可以直接修改原值：

```go
type User struct {
    Name string
    Age  int
}

func (u *User) Birthday() {
    u.Age++
}

u := User{Name: "Tom", Age: 18}
u.Birthday()

fmt.Println(u.Age) // 19
```

调用 `u.Birthday()` 时，编译器会自动转换成 `(&u).Birthday()`，前提是 `u` 可寻址。

指针接收者适合：

- 需要修改接收者
- 接收者较大，避免复制
- 同一类型的其他方法已经使用指针接收者

## 方法集

类型的**方法集**就是"它有哪些方法"，规则两条：

| 类型 | 方法集                            |
| ---- | --------------------------------- |
| `T`  | 所有**值接收者**方法              |
| `*T` | 值接收者方法 + **指针接收者**方法 |

```go
type Counter int

func (c Counter) Value() int { return int(c) } // 在 T 和 *T 的方法集里
func (c *Counter) Inc()      { *c++ }          // 只在 *T 的方法集里
```

对写代码的人，它有两处实际影响：**同一类型的方法要统一接收者**（混用会让 `T` 和 `*T` 能调的方法对不上）；以及**谁能满足接口**——判定表、常见报错和修法都在 `12-接口.md` 的“谁满足接口：方法集判定表”一节。嵌入类型的方法会被提升进外层的方法集，见下文“嵌入与方法提升”一节。

## 自动取地址与自动解引用

如果变量可寻址，Go 允许用值调用指针接收者方法：

```go
var c Counter
c.Inc() // 自动变成 (&c).Inc()
```

反过来，不可寻址的值就不能这么用——**map 元素和函数返回值是最常撞上的两个**：

```go
m := map[string]Counter{"a": 1}

// m["a"].Inc() // 编译错误：cannot call pointer method Inc on Counter

// getCounter().Inc() // 同样报错：函数返回值不可寻址

v := m["a"] // 要改就先取出来，改完放回去
v.Inc()
m["a"] = v
```

哪些表达式可寻址、哪些不行，见 `10-指针.md` 的“什么能取地址”一节。

反方向的自动转换是解引用：也允许用指针调用值接收者方法：

```go
c := Counter(1)
p := &c

fmt.Println(p.Value()) // 自动变成 (*p).Value()
```

但**接口实现**要严格看方法集：`Counter` 不实现含 `Inc` 的接口，`*Counter` 才实现——判定表、常见报错和修法见 `12-接口.md` 的“谁满足接口：方法集判定表”一节。

## nil 接收者

指针接收者的方法可以在 `nil` 指针上调用，前提是方法内部不去解引用它。这不是奇技淫巧，树、链表这类结构天然需要：

```go
type Node struct {
    Val  int
    Next *Node
}

func (n *Node) Sum() int {
    if n == nil { // 递归到链尾时收到的就是 nil
        return 0
    }
    return n.Val + n.Next.Sum()
}

var n *Node

fmt.Println(n.Sum()) // 0 —— nil 接收者不会 panic

head := &Node{Val: 1, Next: &Node{Val: 2}}

fmt.Println(head.Sum()) // 3
```

标准库也用这条约定：`go/types` 的 `(*TypeParamList).Len` 文档写的就是 "It is safe to call on a nil receiver."，实现上先用一个内部方法判掉 `l == nil`。

要注意它和"嵌入的接口字段为 nil"不是一回事：后者的接口动态类型是 nil，调用提升来的方法一定 panic（见下文“嵌入与方法提升”一节）。

## 方法值

方法可以绑定到具体接收者，形成函数值：

```go
u := User{Name: "Tom"}

hello := u.Hello
fmt.Println(hello()) // hello, Tom —— 接收者在绑定时就保存下来了
```

方法值保存了接收者，可以稍后调用。保存的是**副本还是指针**取决于接收者类型——值接收者拿到的是当时的快照，指针接收者拿到的是变量本身，之后对变量的修改它看得见：

```go
type User struct {
    Name string
}

func (u User) Hello() string { return "hello, " + u.Name }

type Counter int

func (c *Counter) Inc() { *c++ }

u := User{Name: "a"}

hello := u.Hello // 值接收者：绑定时复制了一份
u.Name = "b"

fmt.Println(hello()) // hello, a —— 快照没变

c := Counter(1)

inc := c.Inc // 指针接收者：保存的是 &c
c = 100
inc()

fmt.Println(c) // 101 —— 操作的就是这个变量
```

同一个道理，`defer u.Close()` 里的接收者在 `defer` 语句执行时就求值了（`defer` 参数的求值时机见 `04-函数.md`）。

## 方法表达式

方法表达式把接收者作为第一个参数：

```go
hello := User.Hello
fmt.Println(hello(User{Name: "Tom"})) // hello, Tom —— 与方法值等价，只是接收者要显式传入
```

指针接收者方法表达式：

```go
type User struct {
    Name string
    Age  int
}

func (u *User) Birthday() {
    u.Age++
}

birthday := (*User).Birthday
u := User{Name: "Tom", Age: 18}

birthday(&u)
fmt.Println(u.Age) // 19
```

方法表达式在需要传递方法作为普通函数时有用。

## 方法的接收者类型

接收者的**基类型**必须是当前包中定义的命名类型，不能是指针类型或接口类型。这个限制约束的是基类型；接收者本身写成 `T` 或 `*T` 都是合法的，前面用到的 `func (u User)` 和 `func (u *User)` 就是这两种形式。

```go
type MyInt int

func (m MyInt) Double() MyInt {
    return m * 2
}
```

不能给内置类型直接添加方法：

```go
// func (i int) Double() int { ... } // 非法
```

也不能给其他包定义的类型添加方法：

```go
// func (u time.Time) Hello() string { ... } // 非法
```

如果确实需要扩展，可以定义自己的新类型。

```go
type MyTime time.Time
```

## 嵌入与方法提升

嵌入类型的方法会被提升到外层类型，外层可以直接调用（嵌入本身、提升字段的规则见 `09-struct.md`）：

```go
func (p Person) Hello() string { return "hello, " + p.Name }

fmt.Println(Employee{Person: Person{Name: "Tom"}}.Hello()) // hello, Tom
```

被提升的方法**计入外层类型的方法集**，所以外层类型也因此实现了相应的接口。这一点在嵌入的是接口类型时最有用——不用手写一层转发方法，外层就获得了接口里的全部方法：

```go
type Talker interface {
    Talk() string
}

type Robot struct {
    ID int
}

func (r Robot) Talk() string {
    return "beep"
}

// 结构体嵌入接口：Companion 自动拥有 Talk 方法
type Companion struct {
    Talker
    Name string
}

c := Companion{Talker: Robot{ID: 7}, Name: "Tom"}

fmt.Println(c.Talk()) // beep，等于 c.Talker.Talk()

var t Talker = c // Companion 的方法集里有 Talk，所以它本身也实现了 Talker
fmt.Println(t.Talk()) // beep
```

嵌入的接口字段**没赋值时是 `nil`**，此时调用提升来的方法会 panic（接口的动态类型为 nil）：

```go
type Talker interface {
    Talk() string
}

type Companion struct {
    Talker
    Name string
}

var c2 Companion

fmt.Println(c2.Talker == nil) // true

// c2.Talk() // panic：接口的动态类型为 nil
```

两条冲突规则要注意：

- 如果外层类型**自己定义**了同名方法，外层方法优先，被嵌入类型的同名方法被遮蔽。
- 如果两个**同深度**的嵌入类型都提供同名方法，选择器就是非法的（`ambiguous selector`），必须写完整路径，例如 `e.Person.Hello()`。

还有一个现实后果：被提升的方法**成为外层类型公开 API 的一部分**——嵌入 `sync.Mutex` 就等于把 `Lock`/`Unlock` 暴露给使用者，而且外层类型的值副本会带着锁一起复制，`go vet` 会直接报 `passes lock by value`。要加锁就写成命名字段 `mu sync.Mutex`，别嵌入。

## 重名规则

同一个接收者基类型上，方法名必须唯一，结构体的字段名和方法名也不能同名（Go 区分大小写，所以 `name` 字段和 `Name` 方法并不冲突）：

```go
// type User struct {
//     Name string
// }
//
// func (u User) Name() string { // 非法：和字段 Name 冲突
//     return u.Name
// }
```

## 方法与接口

实现了接口方法集的类型就可以赋给接口变量；具体到"值接收者 / 指针接收者分别让谁满足接口"，判定表与常见报错见 `12-接口.md` 的“谁满足接口：方法集判定表”一节。

实现 `String() string` 是最常见的写方法动机之一：`fmt` 会优先使用它的输出，见 `12-接口.md` 的“fmt.Stringer”一节。

接口的隐式实现、类型断言和类型 switch 见 `12-接口.md`。

## Go 1.27 与泛型方法

Go 1.27 起，**方法本身可以声明类型参数**（泛型方法），它和泛型函数一样必须先实例化才能调用或当作函数值使用。两条结论对写方法的人最要紧：

- 接收者的类型参数来自类型定义（`func (l List[E]) ...`），方法自己的类型参数写在接收者之后；调用时自己的类型参数通常能从实参推断出来。
- 接口方法**不能**声明类型参数，泛型方法也因此无法用接口描述——需要运行时多态就还是用普通接口（见 `12-接口.md`）。

完整的语法、实例化方式、多类型参数示例和三条边界见 `13-泛型与类型系统.md`。
