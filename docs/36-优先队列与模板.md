# 36 优先队列与模板

> Go 版本：>= 1.27.1  
> 相关标准库：container/heap、text/template、html/template

本篇讲两个标准库小包：`container/heap`（优先队列）与 `text/template`（文本渲染与代码生成，输出 HTML 时换 `html/template`）。两节之间没有依赖关系，可以按需跳读；查标准库的入口是 `go doc`（见 `00-工具链.md` 的“go doc：查标准库”一节）。

## container/heap

`container/heap` 实现二叉堆，是标准库里唯一的**优先队列**：需要不断插入元素、并反复取出当前最小（或最大）元素时用它。

代价是它要求你的容器类型实现 `heap.Interface`，也就是 `sort.Interface` 的三个方法加上 `Push(any)`、`Pop() any`。定义和用法可以放在一段里看完（`Priority` 数字小的先出队，要反过来就改 `Less`）：

```go
type Task struct {
    Name     string
    Priority int
}

type TaskQueue []Task

func (q TaskQueue) Len() int           { return len(q) }
func (q TaskQueue) Less(i, j int) bool { return q[i].Priority < q[j].Priority }
func (q TaskQueue) Swap(i, j int)      { q[i], q[j] = q[j], q[i] }

func (q *TaskQueue) Push(x any) { *q = append(*q, x.(Task)) }

func (q *TaskQueue) Pop() any {
    // 只移除并返回最后一个元素
    old := *q
    n := len(old)
    item := old[n-1]
    *q = old[:n-1]
    return item
}

q := TaskQueue{
    {Name: "write", Priority: 2},
    {Name: "deploy", Priority: 3},
    {Name: "fix", Priority: 1},
}

heap.Init(&q) // 把已有的切片整理成堆：O(n)

heap.Push(&q, Task{Name: "review", Priority: 4}) // 插入后自动上浮

first := heap.Pop(&q).(Task) // 取出当前最小的
second := heap.Pop(&q).(Task)

fmt.Println(first.Priority, first.Name)   // 1
fmt.Println(second.Priority, second.Name) // 2
```

自己的 `Pop` **只需要移除并返回末尾元素**：堆包会先把目标元素换到末尾再调用它，所以不要在里面写 `old[0]`。

三点容易踩的地方：`heap.Push` 收 `any`、`heap.Pop` 返回 `any`，所以插入直接给 `Task`、取出要写 `.(Task)`（断言失败会 panic，这正是下面说的成本之一）；`Push` 必须调 `heap.Push`，上面那个 `Push` 方法只负责把元素追加到末尾，"上浮"是包级函数干的；堆里元素的顺序**不是排好序的全序**，只有"每次取出的都是当前最小"这一条保证。

改优先级后修复堆用 `heap.Fix(&q, i)`，删除任意位置用 `heap.Remove(&q, i)`，两个都要先知道下标 `i`。

不过绝大多数情况下你并不需要它：

- **只是想要一个排好序的结果**，用 `slices.Sort`——一行、O(n log n)，代码量和心智负担都小得多。
- **只要前 k 个**（排行榜、TopN）也可以先 `slices.Sort` 再切前 k 个：O(n log n) 与堆的 O(n + k log n) 在小数据量上差别可以忽略，只有当 k 远小于 n、或者数据是**流式到达**时才值得上堆。
- 只有“**边插边取最值**”这个模式才能体现堆的优势；一次性取最值用 `slices.Min`/`Max`，批量排序用 `slices.Sort`。
- `Push`/`Pop` 收的是 `any`，每次都要类型断言；需要泛型堆时通常引第三方库，或者干脆自己写一个几十行的 `siftUp`/`siftDown`。

## text/template

下面换一个方向：`text/template` 是标准库的模板引擎，也是**做代码生成的标准做法**——把重复的样板写成模板，用数据驱动生成，Go 官方工具里大量使用它。

基本流程是 `template.New` 命名、`Parse` 解析、`Execute` 渲染：

```go
type User struct {
    Name string
    Tags []string
}

t := template.Must(template.New("user").Parse("hello {{.Name}}\n{{range .Tags}}- {{.}}\n{{end}}"))

u := User{Name: "Tom", Tags: []string{"go", "sql"}}

if err := t.Execute(os.Stdout, u); err != nil {
    return err
}

// hello Tom
// - go
// - sql
```

`{{.Field}}` 取当前数据（dot）的字段，`{{range}}` 遍历切片、数组、map，`{{if}}`、`{{with}}`、`{{end}}` 控制流程，`{{/* 注释 */}}` 写注释。字段必须是导出字段；访问不存在的字段不会打印空值，而是在执行时报错 `can't evaluate field Missing in type main.User`，这也是模板错误必须检查 `Execute` 返回值的原因。

`{{if}}` 和 `{{with}}` 最容易混：两者都按真假决定要不要渲染块内的内容，但 **`{{if}}` 不改变 dot，`{{with}}` 会把 dot 换成这个值**，所以 `{{with .Name}}` 里面要写 `{{.}}`，写 `{{.Name}}` 会报错。值为空（`false`、`0`、空串、`nil`、空切片/map）时整块跳过，可以配 `{{else}}`：

```go
type User struct {
    Name string
}

u := User{Name: "Tom"}

var b strings.Builder

ifT := template.Must(template.New("if").Parse("{{if .Name}}[{{.Name}}]{{end}}"))
withT := template.Must(template.New("with").Parse("{{with .Name}}[{{.}}]{{end}}"))
emptyT := template.Must(template.New("empty").Parse("{{with .Name}}{{.}}{{else}}<empty>{{end}}"))

ifT.Execute(&b, u)
fmt.Println(b.String()) // [Tom] —— if 里 dot 没变，块内还能用 .Name

b.Reset()
withT.Execute(&b, u)
fmt.Println(b.String()) // [Tom] —— with 把 dot 换成了字符串本身，所以写 {{.}}

b.Reset()
emptyT.Execute(&b, User{})
fmt.Println(b.String()) // <empty> —— 值为空时整块跳过，走 else
```

（这里的 `Execute` 返回值为了聚焦 action 省略了，实际代码要像上面那样检查。）

生成代码的典型写法：

```go
t := template.Must(template.New("gen").Parse(`type {{.Name}} struct {
    ID int
}
`))

err := t.Execute(os.Stdout, struct{ Name string }{Name: "Item"})
// type Item struct {
//     ID int
// }
```

`Parse` 返回的 error 交给 `template.Must` 处理，解析期的错误会直接 panic，适合写在包级变量初始化里；运行期的错误通过 `Execute` 的返回值检查。

**生成代码时第一件要处理的事是空白**：模板里的换行和缩进会原样进入输出，`{{range}}`、`{{if}}` 各自占一行的话，每轮都会多出一个空行。用 `{{-` 和 `-}}` 可以吃掉标记**两侧**的空白：

```go
type User struct {
    Tags []string
}

u := User{Tags: []string{"go", "sql"}}

// 标记独占一行且不加短横线：换行留在输出里
loose := template.Must(template.New("loose").Parse("a\n{{range .Tags}}\n  - {{.}}\n{{end}}b\n"))
// 加了短横线：标记两侧的空白被吃掉
tight := template.Must(template.New("tight").Parse("a\n{{- range .Tags}}\n  - {{.}}\n{{- end}}\nb\n"))

var b strings.Builder

loose.Execute(&b, u)
fmt.Printf("%q\n", b.String()) // "a\n\n  - go\n\n  - sql\nb\n" —— 每轮多一个空行

b.Reset()
tight.Execute(&b, u)
fmt.Printf("%q\n", b.String()) // "a\n  - go\n  - sql\nb\n" —— 正是想要的输出
```

需要自定义函数（例如大小写转换、命名风格转换）时用 `Funcs` 注册，并且必须在 `Parse` 之前注册：

```go
t := template.New("gen").Funcs(template.FuncMap{
    "upper": strings.ToUpper,
})

t, err := t.Parse(`{{upper .Name}}`)
```

注册后可以写 `{{upper .Name}}`，也可以写成管道形式 `{{.Name | upper}}`——管道把前一步的结果作为**最后一个参数**传给后一个函数。

模板变多以后需要复用：`{{define "名字"}}` 定义一段命名模板，`{{template "名字" 数据}}` 引用它（第二个参数是新 dot），`{{block "名字" 数据}}` 则是"带默认实现的 template"——先渲染默认内容，之后可以被同名的 `define` 覆盖：

```go
type User struct {
    Tags []string
}

u := User{Tags: []string{"go", "sql"}}

var b strings.Builder

page := template.Must(template.New("page").Parse(`{{define "row"}}[{{.}}]{{end}}{{range .Tags}}{{template "row" .}}{{end}}`))

page.Execute(&b, u)
fmt.Println(b.String()) // [go][sql]

base := template.Must(template.New("base").Parse(`{{block "row" .}}<default>{{end}}`))

b.Reset()
base.Execute(&b, u)
fmt.Println(b.String()) // <default> —— 还没人覆盖，走 block 里的默认内容

base = template.Must(base.Parse(`{{define "row"}}<override>{{end}}`))

b.Reset()
base.Execute(&b, u)
fmt.Println(b.String()) // <override> —— 同名 define 覆盖掉了默认内容
```

`text/template` **不做任何转义**，它的安全模型假设模板作者可信，渲染结果会原样输出。输出 HTML 时用 `html/template`：接口完全一样，但会按上下文自动做 HTML、JS、URL 转义。

### 缺键默认是静默的：missingkey

字段访问的报错只覆盖**结构体字段不存在**（结构体是静态的，`Parse` 就能查出来）。换成 map 就没人拦你了——缺键默认渲染成 `<no value>`，页面照常返回 200：

```go
type Row map[string]string

t := template.Must(template.New("row").Parse("[{{.Missing}}]"))

var b strings.Builder

t.Execute(&b, Row{})
fmt.Println(b.String()) // [<no value>] —— 不报错，线上只会看到这个占位
```

数据来自 map、JSON 或配置时这很危险，用 `Option("missingkey=error")` 把它变成执行期错误：

```go
type Row map[string]string

t := template.Must(template.New("row").Option("missingkey=error").Parse("[{{.Missing}}]"))

var b strings.Builder

err := t.Execute(&b, Row{})
fmt.Println(err != nil) // true —— 同类错误不再静默
```

`Option` 必须在 `Parse` 之前调用（和 `Funcs` 一样），可选的取值还有 `missingkey=default`（默认行为）与 `missingkey=zero`（渲染零值）。注意它只对 **map 的键**生效：结构体字段不存在仍然在 `Parse`/`Execute` 时报错，那一条本来就拦得住。

### 模板多了以后：从文件与 fs.FS 加载

前面都用字符串字面量，实际项目里模板放在文件里。`ParseFS` 一次解析一组文件（`ParseFiles`/`ParseGlob` 是它的前身，针对磁盘路径），每个文件会以**文件名**注册成命名模板，用 `ExecuteTemplate` 指定渲染哪一个：

```go
tplFS := fstest.MapFS{
    "templates/mail.tmpl": &fstest.MapFile{Data: []byte(`{{define "body"}}hi {{.Name}}{{end}}`)},
}

t := template.Must(template.New("mail").ParseFS(tplFS, "templates/*.tmpl"))

var b strings.Builder

if err := t.ExecuteTemplate(&b, "body", map[string]string{"Name": "Tom"}); err != nil {
    fmt.Println(err)
    return
}

fmt.Println(b.String()) // hi Tom
```

`ParseFS` 收的是 `fs.FS`，所以把模板目录用 `embed.FS` 嵌进二进制、或者用 `os.DirFS` 读磁盘，是同一行代码——`embed` 的用法见 `23-路径与文件系统抽象.md` 的"embed"一节。
