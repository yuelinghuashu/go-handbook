# 22 文件与目录操作

> Go 版本：>= 1.27.1  
> 相关标准库：os、io、path/filepath、errors、io/fs

文件是 `io.Reader`/`io.Writer` 最常见的实现，但接口本身在 `21-io与流.md`。

这一篇讲**真实磁盘上**的文件与目录：读、写、列目录、看信息、权限、临时文件，以及把操作限制在一个根目录里的 `os.Root`。把文件系统当接口用（`io/fs`、内存文件系统、嵌入文件）和路径处理在 `23-路径与文件系统抽象.md`。

## os 文件操作

每个例子都自带 `os.MkdirTemp` 造出来的素材，可以直接跑；真实项目里把那些路径换成你自己的。

### 读取文件

```go
dir, err := os.MkdirTemp("", "read-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

path := filepath.Join(dir, "config.json")
if err := os.WriteFile(path, []byte(`{"port":8080}`), 0o644); err != nil {
    log.Fatal(err)
}

data, err := os.ReadFile(path) // 小文件一次读进内存，省得自己管句柄
if err != nil {
    log.Fatal(fmt.Errorf("read %s: %w", path, err))
}

fmt.Printf("%s\n", data) // {"port":8080}
```

大文件别走这条路：`os.ReadFile` 会把整份内容读进内存并一直占着，改用 `os.Open` + `io.Copy`（或 `bufio`）流式处理，见 `21-io与流.md` 的“复制数据”一节。

### 写入文件

```go
dir, err := os.MkdirTemp("", "write-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

path := filepath.Join(dir, "out.txt")

// WriteFile 内部就是 Create + Write + Close，并把 Close 的错误一起返回
if err := os.WriteFile(path, []byte("hello"), 0o644); err != nil {
    log.Fatal(fmt.Errorf("write %s: %w", path, err))
}

info, err := os.Stat(path)
if err != nil {
    log.Fatal(fmt.Errorf("stat %s: %w", path, err))
}

fmt.Println(info.Size()) // 5
```

### 创建文件

```go
dir, err := os.MkdirTemp("", "create-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

path := filepath.Join(dir, "out.txt")

f, err := os.Create(path) // 等价于 OpenFile(path, O_RDWR|O_CREATE|O_TRUNC, 0o666)
if err != nil {
    log.Fatal(fmt.Errorf("create %s: %w", path, err))
}

if _, err := f.WriteString("hello"); err != nil {
    f.Close()
    log.Fatal(fmt.Errorf("write %s: %w", path, err))
}

// 写句柄的 Close 会把缓冲落盘，它是最后一个能报出写失败的地方，不能 defer 了事
if err := f.Close(); err != nil {
    log.Fatal(fmt.Errorf("close %s: %w", path, err))
}

info, err := os.Stat(path)
if err != nil {
    log.Fatal(fmt.Errorf("stat %s: %w", path, err))
}

fmt.Println(info.Size()) // 5
```

写文件时 `Close` 的错误必须检查：数据可能还在缓冲区里，`Write` 返回 `nil` 不代表已经落盘。只读的 `os.Open`、`os.OpenFile` 才可以直接 `defer f.Close()`。

### 打开文件与打开模式

`os.Open(name)` 就是 `os.OpenFile(name, os.O_RDONLY, 0)`；要写就得把访问模式换成 `O_WRONLY`/`O_RDWR`，再按需要叠加下面几个：

| flag                                  | 含义                             | 什么时候用                             |
| ------------------------------------- | -------------------------------- | -------------------------------------- |
| `os.O_RDONLY` / `O_WRONLY` / `O_RDWR` | 访问模式，三选一                 | `os.Open` 固定是 `O_RDONLY`            |
| `os.O_CREATE`                         | 不存在就创建                     | 配置、日志这类"首次运行也要成功"的文件 |
| `os.O_TRUNC`                          | 打开时清空                       | 整体重写                               |
| `os.O_APPEND`                         | 每次都写到末尾                   | 追加日志                               |
| `os.O_EXCL`                           | 与 `O_CREATE` 同用，已存在就报错 | 抢锁文件（见"判断存在与占用"）         |

```go
dir, err := os.MkdirTemp("", "open-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

path := filepath.Join(dir, "data.txt")
if err := os.WriteFile(path, []byte("hello"), 0o644); err != nil {
    log.Fatal(err)
}

f, err := os.OpenFile(path, os.O_RDWR, 0o644)
if err != nil {
    log.Fatal(fmt.Errorf("open %s: %w", path, err))
}
defer f.Close() // 只读句柄的 Close 错误可以忽略，写过的句柄要查（见上一节）

if _, err := f.WriteString("HELLO"); err != nil {
    log.Fatal(fmt.Errorf("write %s: %w", path, err))
}

if _, err := f.Seek(0, io.SeekStart); err != nil { // O_RDWR：写完还能读回来
    log.Fatal(fmt.Errorf("seek %s: %w", path, err))
}

data, err := io.ReadAll(f)
if err != nil {
    log.Fatal(fmt.Errorf("read %s: %w", path, err))
}

fmt.Printf("%q\n", data) // "HELLO"
```

### 目录操作

```go
func dirOps(dir string) error {
    // Mkdir 只建一层、目录已存在会报错；MkdirAll 把中间层一起建好，已存在也不报错
    if err := os.Mkdir(filepath.Join(dir, "data"), 0o755); err != nil {
        return fmt.Errorf("mkdir data: %w", err)
    }
    if err := os.MkdirAll(filepath.Join(dir, "a/b/c"), 0o755); err != nil {
        return fmt.Errorf("mkdir a/b/c: %w", err)
    }

    // Rename 改名，Remove 删文件或空目录，RemoveAll 连里面的内容一起删
    old := filepath.Join(dir, "old.txt")
    if err := os.WriteFile(old, []byte("hi"), 0o644); err != nil {
        return fmt.Errorf("write old.txt: %w", err)
    }
    if err := os.Rename(old, filepath.Join(dir, "new.txt")); err != nil {
        return fmt.Errorf("rename old.txt: %w", err)
    }
    if err := os.Remove(filepath.Join(dir, "new.txt")); err != nil {
        return fmt.Errorf("remove new.txt: %w", err)
    }
    if err := os.RemoveAll(filepath.Join(dir, "a")); err != nil {
        return fmt.Errorf("remove a: %w", err)
    }
    return nil
}

dir, err := os.MkdirTemp("", "dirops-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

if err := dirOps(dir); err != nil {
    log.Fatal(err)
}

entries, err := os.ReadDir(dir)
if err != nil {
    log.Fatal(fmt.Errorf("read dir %s: %w", dir, err))
}

fmt.Println(len(entries) == 1 && entries[0].Name() == "data") // true
```

### 列出目录内容

先看你要什么，再挑工具：

| 你要什么               | 用什么                                                                              | 注意                                                                   |
| ---------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 整个目录，按文件名排序 | `os.ReadDir`                                                                        | 返回 `[]fs.DirEntry`，只读名字与类型，不额外 `stat`                    |
| 条目太多，想分批处理   | `os.Open` + `f.ReadDir(n)`                                                          | 按目录原始顺序、不排序，读到 `io.EOF` 结束                             |
| 递归整棵树             | `filepath.WalkDir`（路径带系统分隔符）/ `fs.WalkDir` + `os.DirFS`（路径统一用 `/`） | 排序规则与提前收手（`SkipDir`/`SkipAll`）见 `23-路径与文件系统抽象.md` |

最常用的是第一种，`os.ReadDir` 是现在列目录的推荐方式，返回 `[]os.DirEntry`（即 `fs.DirEntry`），并且**已经按文件名排好序**：

```go
func listNames(dir string) ([]string, error) {
    entries, err := os.ReadDir(dir)
    if err != nil {
        return nil, fmt.Errorf("read dir %s: %w", dir, err)
    }

    var names []string
    for _, e := range entries {
        names = append(names, e.Name())
    }
    return names, nil
}

dir, err := os.MkdirTemp("", "readdir-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

// 故意按 b、a 的顺序写进去
for _, name := range []string{"b.txt", "a.txt"} {
    if err := os.WriteFile(filepath.Join(dir, name), []byte(name), 0o644); err != nil {
        log.Fatal(err)
    }
}

names, err := listNames(dir)
if err != nil {
    log.Fatal(err)
}

fmt.Printf("%q\n", names) // ["a.txt" "b.txt"]：读出来是按文件名排好序的
```

`DirEntry` 只携带目录项本身的信息：`Name()`、`IsDir()`、`Type()` 通常不需要额外系统调用，要拿大小、时间这类详细信息时再调用 `e.Info()`（会触发一次 `stat`）。所以只筛目录名时用 `os.ReadDir` 比拿 `[]fs.FileInfo` 便宜得多；`ioutil.ReadDir` 已废弃，它正是每个条目都要 `stat` 一遍的旧写法。

`os.Open` + `f.ReadDir(n)` 是更底层的形式，**按目录原始顺序返回、不排序**；`n > 0` 时一次读一批，适合目录特别大、想边读边处理的情况：

```go
func batchSizes(dir string, n int) ([]int, error) {
    f, err := os.Open(dir)
    if err != nil {
        return nil, fmt.Errorf("open dir %s: %w", dir, err)
    }
    defer f.Close()

    var sizes []int
    for {
        batch, err := f.ReadDir(n)
        sizes = append(sizes, len(batch))
        if errors.Is(err, io.EOF) {
            return sizes, nil // 最后一批：0 条 + io.EOF
        }
        if err != nil {
            return nil, fmt.Errorf("read dir %s: %w", dir, err)
        }
    }
}

dir, err := os.MkdirTemp("", "batch-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

for i := range 5 {
    if err := os.WriteFile(filepath.Join(dir, fmt.Sprintf("%d.txt", i)), nil, 0o644); err != nil {
        log.Fatal(err)
    }
}

sizes, err := batchSizes(dir, 2) // 一批最多 2 条；n <= 0 表示一次读完
if err != nil {
    log.Fatal(err)
}

fmt.Println(sizes) // [2 2 1 0]：最后一批是 0 条 + io.EOF
```

### 查看文件信息与符号链接

```go
dir, err := os.MkdirTemp("", "stat-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

path := filepath.Join(dir, "data.txt")
if err := os.WriteFile(path, []byte("hello"), 0o644); err != nil {
    log.Fatal(err)
}

info, err := os.Stat(path)
if err != nil {
    log.Fatal(fmt.Errorf("stat %s: %w", path, err))
}

fmt.Println(info.Name() == "data.txt", info.Size()) // true 5
fmt.Println(info.Mode().IsRegular())                // true：普通文件

// Lstat 看链接本身，Stat 会跟过去
link := filepath.Join(dir, "link")
if err := os.Symlink(path, link); err != nil {
    log.Fatal(fmt.Errorf("symlink %s: %w", link, err))
}

l, err := os.Lstat(link)
if err != nil {
    log.Fatal(fmt.Errorf("lstat %s: %w", link, err)) // 路径不存在或没有权限时 l 为 nil，必须先判错
}

fmt.Println(l.Mode()&os.ModeSymlink != 0) // true：Lstat 看的是链接本身

followed, err := os.Stat(link)
if err != nil {
    log.Fatal(fmt.Errorf("stat %s: %w", link, err))
}

fmt.Println(followed.Mode().IsRegular(), followed.Size()) // true 5：Stat 拿到的是目标的信息
```

`info` 上还有 `ModTime()`（最后修改时间）和 `Mode()`（类型位 + 权限位，权限位受 umask 影响，见下一节）；这两项随环境变化，例子里不拿它们当断言。（Windows 上创建符号链接需要额外权限，这一段在 Linux/macOS 上可以直接跑。）

### 权限与 umask

`0644` 这类数字是八进制权限位，九位分别对应 owner/group/other 的 rwx：

- `0644` = `rw-r--r--`：属主可读写，其他人只读。普通文件、配置文件的默认选择。
- `0755` = `rwxr-xr-x`：属主可读写执行，其他人可读可执行。可执行文件、需要被进入的目录。
- `0600` / `0700`：只有属主可访问，适合密钥、临时文件。

传入的模式只是**请求值**，最终权限是 `perm &^ umask`（按位清掉 umask 中的位）。umask 是**进程级**设置，随环境和容器变化（Windows 上也没有这个概念），所以不要把它当成固定值：

```go
dir, err := os.MkdirTemp("", "umask-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

name := filepath.Join(dir, "out.sh")
if err := os.WriteFile(name, []byte("#!/bin/sh\n"), 0o777); err != nil {
    log.Fatal(fmt.Errorf("write %s: %w", name, err))
}

// 0777 只是请求值：真正落盘的是"请求值 &^ umask"。这里把算式跑一遍
const umask = 0o022
fmt.Printf("%04o\n", 0o777&^umask) // 0755

// 要确定的权限就显式 Chmod：它不受 umask 影响，读回来就是你要的值
if err := os.Chmod(name, 0o644); err != nil {
    log.Fatal(fmt.Errorf("chmod %s: %w", name, err))
}

info, err := os.Stat(name)
if err != nil {
    log.Fatal(fmt.Errorf("stat %s: %w", name, err))
}

fmt.Printf("%04o\n", info.Mode().Perm())                  // 0644：只要权限位
fmt.Println(info.Mode().IsRegular(), info.Mode().IsDir()) // true false
```

`os.OpenFile` 的文档也写作“created with mode perm (**before umask**)”，所以想要确定的结果就不能假设传入值等于实际值。`os.FileMode`（别名 `fs.FileMode`）除了低九位权限，还承载类型位，日常用 `IsRegular()`、`IsDir()`、`Mode()&os.ModeSymlink != 0` 这类方法区分。

### 判断存在与占用

用 `errors.Is` 对照 `os` 导出的哨兵错误做分类，而不是解析错误字符串：

```go
func classify(path string) (string, error) {
    _, err := os.Stat(path)

    switch {
    case err == nil:
        return "存在", nil
    case errors.Is(err, os.ErrNotExist):
        return "不存在", nil
    case errors.Is(err, os.ErrPermission):
        return "没有权限", nil
    default:
        return "", fmt.Errorf("stat %s: %w", path, err) // 其余错误（例如路径中间不是目录）照旧上抛
    }
}

func createExclusive(path string) error {
    f, err := os.OpenFile(path, os.O_CREATE|os.O_EXCL|os.O_WRONLY, 0o644)
    if err != nil {
        return fmt.Errorf("create %s: %w", path, err)
    }

    // 拿到句柄就要负责关：判断完就丢掉 f 会漏文件描述符
    if err := f.Close(); err != nil {
        return fmt.Errorf("close %s: %w", path, err)
    }
    return nil
}

dir, err := os.MkdirTemp("", "exists-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

kind, err := classify(filepath.Join(dir, "config.json")) // 这个文件不存在
if err != nil {
    log.Fatal(err)
}

fmt.Println(kind == "不存在") // true

lock := filepath.Join(dir, "lock")

if err := createExclusive(lock); err != nil {
    log.Fatal(err)
}

// 第二次打开同一个路径：O_EXCL 让它在文件已存在时直接失败
err = createExclusive(lock)

fmt.Println(errors.Is(err, os.ErrExist)) // true
```

`os` 的 `ErrNotExist`、`ErrExist`、`ErrPermission` 等实际就是 `io/fs` 里的同名变量，只是别名，所以 `errors.Is(err, fs.ErrNotExist)` 等价。

`os.IsNotExist`/`os.IsExist` 这些旧函数仍然可用，但官方文档明确说它们“predates errors.Is”，只支持 `os` 包返回的错误，新代码应改用 `errors.Is`（`errors.Is` 还能穿透包装过的错误，旧函数不行）。

### 退出程序

```go
os.Exit(1)
```

`os.Exit` 会立即结束程序，`defer` 不会执行；退出码 1 表示失败，调用方（shell、CI）据此判断。需要"打印一行再退出"就用 `log.Fatal`（见 `27-日志.md`），上面各例已经这么用了。

### 临时文件与临时目录

`os.CreateTemp` 生成一个带随机后缀的文件并打开为读写，模式是 `0600`（before umask）：

```go
func tempJSON(pattern string) (string, error) {
    f, err := os.CreateTemp("", pattern)
    if err != nil {
        return "", fmt.Errorf("create temp file: %w", err)
    }

    name := f.Name()
    if err := f.Close(); err != nil {
        os.Remove(name)
        return "", fmt.Errorf("close %s: %w", name, err)
    }
    return name, nil
}

name, err := tempJSON("app-*.json")
if err != nil {
    log.Fatal(err)
}
defer os.Remove(name) // 清理是调用方的责任

fmt.Println(name)                             // 形如 /tmp/app-1234567890.json：目录来自 os.TempDir()，后缀是随机的
fmt.Println(strings.HasSuffix(name, ".json")) // true：pattern 里最后一个 * 被随机串替换
```

- `dir` 传空字符串时使用 `os.TempDir()`（Unix 上是 `$TMPDIR`，否则 `/tmp`）。
- `pattern` 里最后一个 `*` 会被随机串替换，用来固定前缀/后缀。
- 需要临时目录时用 `os.MkdirTemp(dir, pattern)`，返回路径字符串，模式 `0700`，清理用 `defer os.RemoveAll(dir)`。
- 这两个函数都不负责清理：程序退出后文件会留在磁盘上。

## os.Root

Go 1.24 起，`os.Root` 可以把文件操作限制在一个根目录内：

```go
func readInRoot(root *os.Root, name string) ([]byte, error) {
    f, err := root.Open(name)
    if err != nil {
        return nil, fmt.Errorf("open %s: %w", name, err)
    }
    defer f.Close()

    data, err := io.ReadAll(f)
    if err != nil {
        return nil, fmt.Errorf("read %s: %w", name, err)
    }
    return data, nil
}

dir, err := os.MkdirTemp("", "root-")
if err != nil {
    log.Fatal(err)
}
defer os.RemoveAll(dir)

if err := os.WriteFile(filepath.Join(dir, "config.json"), []byte(`{"port":8080}`), 0o644); err != nil {
    log.Fatal(err)
}

root, err := os.OpenRoot(dir) // 之后用 root 的方法访问文件，路径都相对于 dir
if err != nil {
    log.Fatal(fmt.Errorf("open root %s: %w", dir, err))
}
defer root.Close()

data, err := readInRoot(root, "config.json")
if err != nil {
    log.Fatal(err)
}

fmt.Printf("%s\n", data) // {"port":8080}

// 用 .. 跳出根目录会被拒绝，拿不到根之外的文件
_, err = root.Open("../config.json")

fmt.Println(err != nil) // true
```

`os.Root` 适合处理不可信路径，避免通过 `..` 跳出根目录；被拒绝时返回的是一个 `*os.PathError`，用 `err != nil`（或 `errors.As`）判断即可，别去比对错误文案。路径处理（`path`/`filepath`）与文件系统抽象的其余部分在 `23-路径与文件系统抽象.md`。
