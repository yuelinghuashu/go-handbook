# 29 命令行与正则

> Go 版本：>= 1.27.1  
> 相关标准库：flag、os、regexp

需要解析命令行参数、或者用正则做匹配与替换时，来看本篇：`flag`（加上 `os.Args`）管命令行参数，`regexp` 管文本匹配。两半互不依赖，可以按需跳读。

## os.Args

`os.Args` 保存程序名和原始参数：

```go
fmt.Println(os.Args[0]) // 程序名
fmt.Println(os.Args[1:]) // 参数列表
```

`os.Args` 不处理 flag 语法，需要自己解析时可以使用它。

## flag 包

`flag` 是标准库的命令行参数解析包。

```go
// String / Int / Bool / Duration：各注册一个 flag 并返回它的指针，参数依次是名字、默认值、用法说明
name := flag.String("name", "gopher", "user name")
count := flag.Int("count", 1, "repeat count")
debug := flag.Bool("debug", false, "enable debug")
duration := flag.Duration("timeout", time.Second, "timeout duration")

// Parse：解析命令行并填回上面那些指针（必须在所有注册之后调用）
flag.Parse()

fmt.Println(*name)     // gopher —— 不带参数运行时就是注册时的默认值
fmt.Println(*count)    // 1
fmt.Println(*debug)    // false
fmt.Println(*duration) // 1s
```

### 位置参数

`flag.Parse` 之后的参数可以通过 `flag.Args` 获取：

```go
flag.Parse()

args := flag.Args()
fmt.Println(args) // [] —— 没有位置参数时是空切片；传了参数则形如 [file.txt]
```

### 使用已有变量

```go
var name string
var count int

flag.StringVar(&name, "name", "gopher", "user name")
flag.IntVar(&count, "count", 1, "repeat count")

flag.Parse()
```

### 替代手写 flag.Value：Func、TextVar、BoolFunc

这三个辅助函数替代了大多数手写的 `flag.Value` 实现——**先看它们能不能用**；下一节才是"必须自己实现"的情况。

`flag.Func`（Go 1.16）注册一个“每次出现就调用一次”的回调，不用再定义类型和 `String()`：

```go
var upper string

flag.Func("upper", "uppercase the value", func(v string) error {
    upper = strings.ToUpper(v)
    return nil
})

flag.Parse()
```

回调返回非 nil 错误时就算一次普通的 flag 解析错误（`ExitOnError` 下打印用法并退出），所以校验逻辑可以直接写在里面。需要收集**多次出现的值**时（例如 `-I a -I b`）它同样合适，在回调里往切片里追加即可。

`flag.TextVar`（Go 1.19）用于**已经实现 `encoding.TextUnmarshaler`/`encoding.TextMarshaler`** 的类型，默认值也一并传入：

```go
type Tag string

func (t Tag) MarshalText() ([]byte, error)  { return []byte(t), nil }
func (t *Tag) UnmarshalText(b []byte) error { *t = Tag(b); return nil }

var tag = Tag("dev")

flag.TextVar(&tag, "tag", tag, "tag value")
flag.Parse()
```

签名是 `flag.TextVar(p encoding.TextUnmarshaler, name string, value encoding.TextMarshaler, usage string)`：`p` 必须是指针，默认值的类型必须和 `p` 指向的类型一致。`time.Time` 正好满足这对接口；**`time.Duration` 不满足**（它没有 `MarshalText`/`UnmarshalText`），解析时长继续用 `flag.Duration`。

`flag.BoolFunc`（Go 1.21）注册一个**不需要值**的 flag，写法上和布尔 flag 一样，可以只写名字：

```go
var verbose int

flag.BoolFunc("v", "increase verbosity", func(v string) error {
    if v == "true" {
        verbose++
    }
    return nil
})
```

`-v` 会以 `"true"` 调用回调，`-v=false` 以 `"false"` 调用；多个 `-v -v -v` 就是经典的多级详细度计数。

这三者的"短"是相对**手写 `flag.Value`** 说的；只是想把 flag 绑到已有变量时，`StringVar`/`IntVar` 反而更短，那种情况继续用它们。

### 自定义类型

上面三个辅助函数覆盖不了的场景才需要手写 `flag.Value`，比如 `IsBoolFlag` 这类特殊行为。实现 `flag.Value` 接口：

```go
type Level string

func (l *Level) String() string {
    return string(*l)
}

func (l *Level) Set(v string) error {
    switch v {
    case "debug", "info", "error":
        *l = Level(v)
        return nil
    default:
        return fmt.Errorf("invalid level: %s", v)
    }
}
```

注册：

```go
var level Level

flag.Var(&level, "level", "log level")
flag.Parse()
```

### FlagSet

需要隔离多套参数时使用 `flag.NewFlagSet`：

```go
fs := flag.NewFlagSet("app", flag.ExitOnError)

name := fs.String("name", "gopher", "user name")
fs.Parse(os.Args[1:])

fmt.Println(*name) // gopher —— 没传 -name 时取注册时的默认值
```

### Usage

```go
flag.Usage = func() {
    fmt.Fprintf(flag.CommandLine.Output(), "Usage: %s [options]\n", os.Args[0])
    flag.PrintDefaults()
}

flag.Parse()
```

### flag 语法规则

- `-flag=value` 和 `-flag value`（空格分隔）都合法；
- **布尔 flag 不能用空格形式传值**：布尔 flag 只写名字就表示 `true`，后面的词会被当成位置参数：

```bash
app -v false     # -v 被置为 true，"false" 变成位置参数
app -v=false     # 正确：-v 被置为 false
```

- 单横线和双横线等价：`-name tom` 与 `--name tom` 是同一个 flag；
- `--` 终止 flag 解析，其后的内容全部作为位置参数（透传给子进程时很常用）：

```text
$ app -- -name tom
flag.Args() == []string{"-name", "tom"}
```

- `-h` / `-help` 会打印用法；在 `flag.ExitOnError` 下以状态码 0 退出，未定义 `help` flag 时不需要自己处理；
- 错误处理策略：

```go
flag.ExitOnError     // 出错打印用法并 os.Exit(2)；-h/-help 时 Exit(0)
flag.PanicOnError    // 出错 panic
flag.ContinueOnError // 返回 error，适合库代码和子命令
```

`flag.CommandLine` 用的是 `ExitOnError`，而 `flag.NewFlagSet` 的零值行为是 `ContinueOnError`，所以子命令里可以自己拿到 `Parse` 的返回值。

- `fs.SetOutput(w)` 把用法和错误信息写到指定的 writer，测试里可以 `fs.SetOutput(&buf)` 后断言用法文本；传 `nil` 表示恢复 `os.Stderr`。

```go
fs := flag.NewFlagSet("app", flag.ContinueOnError)

var buf strings.Builder
fs.SetOutput(&buf)

fs.String("name", "gopher", "user name")
_ = fs.Parse([]string{"-h"}) // 触发 Usage

fmt.Print(buf.String())
// Usage of app:
//   -name string
//         user name (default "gopher")
```

### 子命令模式（git 风格）

每个子命令一个独立的 `*FlagSet`，只把自己后面的参数交给它解析：

```go
func main() {
    if len(os.Args) < 2 {
        fmt.Fprintln(os.Stderr, "usage: app <add|list> [options]")
        os.Exit(2)
    }

    switch os.Args[1] {
    case "add":
        fs := flag.NewFlagSet("add", flag.ExitOnError)

        n := fs.Int("n", 1, "repeat count")
        fs.Parse(os.Args[2:]) // 只解析本子命令之后的参数

        fmt.Println("add", *n, fs.Args())

    case "list":
        fs := flag.NewFlagSet("list", flag.ExitOnError)

        all := fs.Bool("all", false, "list all")
        fs.Parse(os.Args[2:])

        fmt.Println("list", *all, fs.Args())

    default:
        fmt.Fprintf(os.Stderr, "unknown subcommand: %s\n", os.Args[1])
        os.Exit(2)
    }
}
```

```text
$ app add -n 3 file.txt
add 3 [file.txt]
```

要点：`FlagSet` 的名字只影响用法文本，真正的隔离来自各自的 flag 集合；把 `os.Args[2:]` 交给子命令后，`os.Args[1]` 这个子命令名不会被子命令当成 flag 解析，各子命令之间也不会抢同一个 `-n`。子命令自己的用法文本可以用 `fs.Usage` + `fs.SetOutput` 定制。

## regexp

命令行参数到此为止，下面换到另一半：文本匹配与替换。两块互不依赖，只看正则的话可以从这里开始读。

`regexp` 提供正则表达式支持，采用 RE2 语法。它的实现**没有回溯（backtracking）**，包文档明确保证 “guaranteed to run in time linear in the size of the input”，因此不会出现灾难性回溯（ReDoS）——匹配时间随输入长度线性增长。

代价是两种常见特性**不被支持**，编译时会直接报错：

```go
_, err := regexp.Compile(`(a)\1`) // 反向引用（backreference）
fmt.Println(err) // error parsing regexp: invalid escape sequence: `\1`

_, err = regexp.Compile(`(?=a)`) // 环视（lookahead / lookbehind）
fmt.Println(err) // error parsing regexp: invalid or unsupported Perl syntax: `(?=`
```

`(?<=...)`、`(?<!...)`、`(?!...)` 同样不可用。需要这些语义时要换思路（例如先粗匹配、再用代码判断），或者引入第三方正则引擎。

另一个容易踩的坑是**字符类的 ASCII 语义**：`\d`、`\w`、`\s`、`\b` 都是 ASCII 专用，`regexp/syntax` 的文档写得很明确——“Perl character classes (all ASCII-only)”，`\d` 等价于 `[0-9]`、`\w` 等价于 `[0-9A-Za-z_]`、`\b` 是 ASCII 词边界。要按 Unicode 语义匹配，请用 `\p{...}`：

```go
re := regexp.MustCompile(`^\d+$`)
fmt.Println(re.MatchString("٣")) // false —— 阿拉伯-印度数字不是 ASCII 的 \d

re = regexp.MustCompile(`^\p{Nd}+$`)
fmt.Println(re.MatchString("٣")) // true —— \p{Nd} 是 Unicode 十进制数字
```

### 编译与匹配

```go
re, err := regexp.Compile(`^[a-z]+$`)
if err != nil {
    fmt.Println(err)
    return
}

fmt.Println(re.MatchString("golang")) // true
fmt.Println(re.MatchString("Go123"))  // false
```

模式字符串既可以是字面量常量，也可以是运行时拼出来的（后者必须处理 `Compile` 返回的 error）。确定不会出错时用 `MustCompile`，它在模式非法时 panic 而不是返回 error：

```go
re := regexp.MustCompile(`\d+`)
```

### 查找

```go
re := regexp.MustCompile(`\d+`)

fmt.Println(re.FindString("abc123def456")) // 123
```

查找所有匹配：

```go
re := regexp.MustCompile(`\d+`)

fmt.Println(re.FindAllString("abc123def456", -1)) // [123 456]
```

限制数量：

```go
fmt.Println(re.FindAllString("abc123def456", 1)) // [123]
```

### 子匹配

```go
re := regexp.MustCompile(`(\w+)=(\w+)`)

match := re.FindStringSubmatch("name=tom")

fmt.Println(match[0]) // name=tom
fmt.Println(match[1]) // name
fmt.Println(match[2]) // tom
```

### 命名子匹配

```go
re := regexp.MustCompile(`(?P<key>\w+)=(?P<value>\w+)`)
match := re.FindStringSubmatch("name=tom")

for i, name := range re.SubexpNames() {
    if name != "" {
        fmt.Println(name, match[i])
    }
}
// key name
// value tom
```

### 子匹配索引

`SubexpIndex`（Go 1.15）用名字换到子匹配在 `FindStringSubmatch` 结果里的下标，比手写遍历 `SubexpNames` 更直接：

```go
re := regexp.MustCompile(`(?P<key>\w+)=(?P<value>\w+)`)

fmt.Println(re.SubexpIndex("key"))   // 1
fmt.Println(re.SubexpIndex("value")) // 2
fmt.Println(re.SubexpIndex("nope"))  // -1

match := re.FindStringSubmatch("name=tom")
fmt.Println(match[re.SubexpIndex("value")]) // tom
```

`FindAllStringSubmatchIndex` 返回所有匹配的**下标对**，适合在原文里定位或做保留原文的替换：

```go
re := regexp.MustCompile(`(\w+)=(\w+)`)
s := "a=1 b=2"

for _, idx := range re.FindAllStringSubmatchIndex(s, -1) {
    fmt.Printf("key=%s value=%s\n", s[idx[2]:idx[3]], s[idx[4]:idx[5]])
}
// key=a value=1
// key=b value=2
```

每个匹配的下标切片结构是 `[整体开始, 整体结束, 第 1 组开始, 第 1 组结束, ...]`；没有参与匹配的组用 `-1` 表示。

### 转义：把用户输入拼进正则

`regexp.QuoteMeta` 转义所有正则元字符，返回一个“只匹配这段字面量”的模式：

```go
user := "a.b(c)"
re := regexp.MustCompile(regexp.QuoteMeta(user))

fmt.Println(regexp.QuoteMeta(user))     // a\.b\(c\)
fmt.Println(re.MatchString("xa.b(c)y")) // true
```

拼接用户输入（搜索框、文件名过滤、`LIKE` 式查询）时**必须**先转义，否则用户输入的 `.`、`*`、`(` 会改变语义，甚至让 `Compile` 直接失败。

### 替换

```go
re := regexp.MustCompile(`\d+`)

result := re.ReplaceAllString("abc123def456", "#")
fmt.Println(result) // abc#def#
```

使用子匹配：

```go
re := regexp.MustCompile(`(\w+)=(\w+)`)

result := re.ReplaceAllString("name=tom", "$1: $2")
fmt.Println(result) // name: tom
```

注意 `ReplaceAllString` 的替换串会经过 `Expand`：里面的 `$1`、`${name}` 会被当成**子匹配引用**展开。所以当替换文本来自用户输入时，必须改用 `ReplaceAllLiteralString`，否则用户写的 `$1` 会被悄悄替换成别的内容：

```go
userRepl := "$1"

fmt.Println(re.ReplaceAllString("name=tom", userRepl))        // name —— $1 被展开成第一个子匹配
fmt.Println(re.ReplaceAllLiteralString("name=tom", userRepl)) // $1  —— 按字面量插入
```

需要“根据匹配到的内容动态决定替换值”时用 `ReplaceAllStringFunc`，回调收到的就是匹配到的子串，返回值也是**按字面量**插入、不走 `Expand`：

```go
fmt.Println(re.ReplaceAllStringFunc("a=1 b=2", strings.ToUpper)) // A=1 B=2
```

### 最长匹配与匹配策略

默认是 leftmost-first（最左优先，且优先选择靠左的分支），和 Perl 一致。`Longest()` 把策略改成 leftmost-longest：

```go
re := regexp.MustCompile(`a|ab`)

fmt.Println(re.FindString("ab")) // a

re.Longest()
fmt.Println(re.FindString("ab")) // ab
```

`Longest` 修改的是 `Regexp` 自身，**不能和其他方法并发调用**，调用后对所有后续匹配生效。

### 分割

```go
re := regexp.MustCompile(`\s*,\s*`)

parts := re.Split("a, b ,c", -1)
fmt.Println(parts) // [a b c]
```

### 性能建议

- **包级编译一次**：`Compile`/`MustCompile` 要做解析并编译成自动机，是重量级操作，把结果放进包级变量复用：

```go
var numRe = regexp.MustCompile(`\d+`) // 包级，只编译一次

func extract(s string) []string {
    return numRe.FindAllString(s, -1)
}
```

- **并发安全**：`*regexp.Regexp` 可以被多个 goroutine 同时使用（包文档：safe for concurrent use by multiple goroutines），所以“包级编译 + 随处使用”是正确写法，不需要自己加锁。例外是 `Longest()` 这类配置方法，必须在开始并发使用之前调用完；`Copy()` 是早期为减少锁竞争而引入的，现在已标记为 Deprecated。
- 简单固定字符串查找优先使用 `strings.Contains`、`strings.Index`、`strings.HasPrefix`。
- 需要在同一段文本上做多次处理后定位，用 `...Index`/`...SubmatchIndex` 系列拿到下标，避免重复扫描。
- 拼接用户输入前先 `regexp.QuoteMeta`，替换用户输入时用 `ReplaceAllLiteralString`。
- 复杂正则可能比手写解析慢很多，热点路径上先测量再优化。
