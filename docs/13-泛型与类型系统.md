# 13 泛型与类型系统

> Go 版本：>= 1.27.1  
> 相关标准库：cmp、slices、maps

读法：**类型参数、类型约束、`comparable`、泛型类型、泛型方法**是主线，第一遍读完这五节就够用了；标了"初读可以跳过"的四节（Go 1.20 对 comparable 的放宽、无类型常量的默认类型、函数类型推断、泛型的实现与性能）属于规范细节与实现细节，等真正用到时再回来查。

## 为什么需要泛型

在泛型出现之前，如果多个类型需要相同的算法，通常只能为每个类型写一份代码：

```go
func SumInts(nums []int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

func SumFloat64s(nums []float64) float64 {
    total := 0.0
    for _, n := range nums {
        total += n
    }
    return total
}
```

也可以使用空接口，但会失去类型检查，并且需要类型断言。

泛型允许把类型作为参数，从而只写一份算法：

```go
func Sum[T int | int64 | float64](nums []T) T {
    var total T
    for _, n := range nums {
        total += n
    }
    return total
}
```

## 类型参数

泛型函数在函数名后声明类型参数；调用时，类型通常可以自动推断：

```go
func Identity[T any](v T) T {
    return v
}

fmt.Println(Identity(1))      // 1
fmt.Println(Identity("hello")) // hello
```

也可以显式指定类型：

```go
fmt.Println(Identity[string]("hello"))
```

类型参数名通常使用单字母大写，例如 `T`、`E`、`K`、`V`。

## 类型约束

类型参数必须满足约束。最简单的约束是 `any`，表示任意类型（Java/C# 的泛型约束是"必须是某个类型的子类"，Go 不是——它的约束描述的是一个**类型集合**，没有继承参与，这一点在"联合约束与 `~`"和"类型集合"两节会展开）：

```go
func Print[T any](v T) {
    fmt.Println(v)
}
```

但 `any` 不允许对 `T` 做运算：

```go
func Add[T any](a, b T) T {
    return a + b // 编译错误：T 不保证支持 +
}
```

需要限制类型范围：

```go
type Number interface {
    ~int | ~int64 | ~float64
}

func Add[T Number](a, b T) T {
    return a + b
}
```

这样 `T` 只能是 `int`、底层为 `int` 的类型、`int64` 或 `float64` 等。

## comparable

`comparable` 是预声明约束，表示类型支持 `==` 和 `!=`：

```go
func Contains[T comparable](s []T, target T) bool {
    for _, v := range s {
        if v == target {
            return true
        }
    }
    return false
}

fmt.Println(Contains([]string{"go", "lang"}, "go")) // true
fmt.Println(Contains([]int{1, 2, 3}, 2))            // true
```

切片、map 和函数不满足 `comparable`：

```go
// Contains([][]int{{1}}, []int{1}) // 非法
```

`comparable` 只说明 `T` 自身可以用 `==` 比较，**对由 `T` 组合出来的类型不提供任何保证**。最典型的是：即使 `T` 是 `comparable`，`[]T` 依然不可比较——切片本身永远不可比较，跟元素类型没有关系。

```go
func EqSlice[T comparable](a, b []T) bool {
    return a == b
}

// invalid operation: a == b (slice can only be compared to nil)
```

在复合类型里，只有结构体和数组可以把元素的可比较性传递上去：结构体在所有字段类型可比较时可用 `==`，数组在元素类型可比较时可用 `==`（见 `09-struct.md`）。需要比较两个 `[]T` 时用 `slices.Equal`（见 `15-slices.md`）。

## 联合约束与 ~

约束可以写成多个类型的联合：

```go
type Integer interface {
    int | int8 | int16 | int32 | int64
}
```

`~T` 表示底层类型是 `T` 的所有类型：

```go
type MyInt int

type TildeInteger interface {
    ~int | ~int64
}

func Double[T TildeInteger](v T) T {
    return v * 2
}

var n MyInt = 3
fmt.Println(Double(n)) // 6
```

`MyInt` 的底层类型是 `int`，因此满足 `~int`；而上面那个不带 `~` 的 `Integer` 只接受 `int`、`int8` 等**类型本身**，自定义类型即使底层是 `int` 也不满足。

### 联合约束要求运算符对每个类型都成立

规范对类型参数的操作数有一条硬性规定：如果操作数的类型是类型参数，**该运算符必须对类型集合中的每一个类型都适用**。这是联合约束最常见的报错来源。

前面定义的 `Number`（`~int | ~int64 | ~float64`）三个类型都支持 `+`，所以 `Add` 可以编译：

```go
type Number interface {
    ~int | ~int64 | ~float64
}

func Add[T Number](a, b T) T {
    return a + b // 合法：三个类型都支持 +
}

fmt.Println(Add(1.5, 2.5)) // 4
```

把 `string` 加进联合后 `*` 就不能用了，因为 `string` 不支持乘法：

```go
type Bad interface {
    ~int | ~string
}

func Mul[T Bad](a, b T) T {
    return a * b // 编译错误：string 不支持 *
}
```

```text
invalid operation: operator * not defined on a (variable of type T constrained by Bad)
```

换成 `-` 也是同样的报错：

```text
invalid operation: operator - not defined on a (variable of type T constrained by Bad)
```

容易踩的一个坑是 `+`：`~int | ~string` 是可以使用 `+` 的，因为整数相加和字符串拼接都写作 `+`，联合里两个类型都支持它。所以判断某个运算符能不能用，要看联合里**每一个**类型是否都支持它，而不是看它们看起来是不是“一类”。

看到 `operator X not defined on a (variable of type T constrained by C)` 这类报错时，先回到约束定义，逐个检查联合中的类型是否都支持 `X`。

## cmp.Ordered

标准库 `cmp.Ordered` 是最常用的有序类型约束（Go 1.21 起，和 `slices`/`maps` 同一批）。自己写约束时如果只是想覆盖"所有有序类型"，直接用它，不必手抄一遍联合——它的定义就是下面这条联合：

```go
type Ordered interface {
    ~int | ~int8 | ~int16 | ~int32 | ~int64 |
        ~uint | ~uint8 | ~uint16 | ~uint32 | ~uint64 | ~uintptr |
        ~float32 | ~float64 |
        ~string
}
```

注意这里每个类型都带 `~`，所以自定义的 `type MyInt int` 也满足 `cmp.Ordered`。

用法：

```go
func Max[T cmp.Ordered](a, b T) T {
    if a > b {
        return a
    }
    return b
}

fmt.Println(Max(1, 2))       // 2
fmt.Println(Max("a", "b"))   // b
```

`cmp` 包还提供 `cmp.Compare`、`cmp.Less`、`cmp.Or` 这组比较函数，以及它们在排序里的用法，见 `17-cmp.md`。

## 类型推断

大多数情况下，编译器可以从参数推断类型参数：

```go
fmt.Println(Identity(42))        // T 推断为 int
fmt.Println(Identity("gopher"))  // T 推断为 string
fmt.Println(Max(1.5, 2.5))       // T 推断为 float64
```

也可以显式实例化：

```go
func Identity[T any](v T) T {
    return v
}

func Max[T cmp.Ordered](a, b T) T {
    if a > b {
        return a
    }
    return b
}

fmt.Println(Identity[float64](1)) // 1
fmt.Println(Max[float64](1.5, 2.5))
```

类型推断失败时，就需要显式写出类型参数。

### 无类型常量的默认类型

**这一节是编译器细节，初读可以跳过**——只要知道 `Max(1, 2)` 里 `T` 是 `int`、`Max(1, 2.5)` 里 `T` 是 `float64` 就够了。

推断会优先使用有类型的操作数提供的信息，无类型常量放在最后处理。当类型参数只和无类型常量配对时，编译器先按常量表达式的规则确定这些常量的 kind，再取该 kind 的默认类型（对应表见 `01-变量与基础类型.md` 的“无类型常量”一节）作为类型实参。所以 `Max(1, 2)` 里的 `1` 和 `2` 都是整数常量，kind 是 integer，默认类型是 `int`：

```go
fmt.Printf("%T\n", Max(1, 2)) // int
```

多个无类型常量会先合成一个 kind，规则和常量表达式的二元运算一致：不同 kind 的无类型操作数参与运算时，结果的 kind 取 integer、rune、floating-point、complex 列表中靠后的那一个。所以 `Max(1, 2.5)` **不会**报错：整数和浮点数混合后 kind 是 floating-point，`T` 推断为 `float64`。

```go
fmt.Printf("%T %v\n", Max(1, 2.5), Max(1, 2.5)) // float64 2.5
```

只有 kind 冲突时推断才会失败，例如整数和字符串：

```go
// fmt.Println(Max(1, "a"))
// in call to Max, mismatched types untyped int and untyped string (cannot infer T)
```

显式实例化可以绕开推断，此时无类型常量按目标类型转换：

```go
func Max[T cmp.Ordered](a, b T) T {
    if a > b {
        return a
    }
    return b
}

fmt.Println(Max[float64](1, 2.5)) // 2.5
fmt.Println(Max[float64](1, 2))   // 2
```

## 泛型类型

类型可以带类型参数，方法接收者要把类型参数一并写出来：

```go
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T) {
    s.items = append(s.items, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.items) == 0 {
        var zero T
        return zero, false
    }

    last := len(s.items) - 1
    v := s.items[last]
    s.items = s.items[:last]

    return v, true
}

var s Stack[int]

s.Push(1)
s.Push(2)

v, ok := s.Pop()
fmt.Println(v, ok) // 2 true
```

`Stack[int]` 是一个具体的、独立的类型，和 `Stack[string]`、`Stack[MyInt]` 都没有关系，即使它们的底层结构一样也不能互相赋值：

```go
var a Stack[int]
var b Stack[string]

// a = b // 非法
// cannot use b (variable of struct type Stack[string]) as Stack[int] value in assignment
```

泛型类型必须先实例化才能当作类型使用，而且类型实参不会从上下文推断，必须写出来：

```go
// var s Stack = Stack[int]{} // 非法
// cannot use generic type Stack[T any] without instantiation
```

泛型类型的方法接收者需要声明与类型定义相同数量的类型参数：

```go
func (s *Stack[T]) Len() int {
    return len(s.items)
}
```

接收者里的类型参数名不必和类型定义中的一致，数量必须一致；这些类型参数的约束由类型定义隐含决定。

## 泛型方法

Go 1.27 支持泛型方法，也就是方法本身可以声明额外的类型参数：

```go
type List[E any] []E

func (l List[E]) Apply[F any](f func(E) F) List[F] {
    r := make(List[F], len(l))

    for i, v := range l {
        r[i] = f(v)
    }

    return r
}

nums := List[int]{1, 2, 3}

fmt.Println(nums.Apply(func(v int) string { return fmt.Sprint(v * 2) })) // [2 4 6]

apply := nums.Apply[string] // 显式实例化成函数值，接收者在那一刻绑定到 nums
fmt.Println(apply(func(int) string { return "x" })) // [x x x]

fmt.Println(nums.Apply[int](func(v int) int { return v + 1 })) // [2 3 4]
```

这里 `List[E]` 是泛型类型，`Apply[F any]` 是带自己类型参数的泛型方法。泛型方法的类型参数和泛型函数一样能从实参推断，接收者的类型参数则来自接收者本身、不用写：第一个调用里 `F` 由 `func(int) string` 推断成 `string`；`nums.Apply[string]` 不推断，直接实例化出一个类型为 `func(func(int) string) List[string]` 的函数值，方法值在实例化那一刻就绑定到 `nums` 上。

方法也可以带多个自己的类型参数，并与接收者的类型参数组合使用：

```go
type List[E any] []E

func (l List[E]) GroupBy[K comparable](key func(E) K) map[K][]E {
    out := make(map[K][]E)

    for _, v := range l {
        k := key(v)
        out[k] = append(out[k], v)
    }

    return out
}

nums := List[int]{1, 2, 3, 4}
fmt.Println(nums.GroupBy(func(v int) int { return v % 2 })) // map[0:[2 4] 1:[1 3]]
```

三条边界需要记住：

- **接口方法不能声明类型参数**：`interface{ M[T any](T) }` 非法，编译器直接报 `interface method must have no type parameters`。接口只能靠**接口自身**的类型参数获得泛型能力（`type Container[T any] interface { Get() T }`）。
- 接收者的类型参数个数必须与类型定义一致（`func (l List[E]) ...`），方法自己的类型参数写在这之后。
- 泛型方法**无法用接口描述**，所以它做不了运行时多态——需要多态时仍然用普通接口（见 `12-接口.md`）。

## 泛型类型别名

Go 1.24 起，类型别名也可以带类型参数，使用时必须实例化：

```go
type IntSlice = []int
type Slice[T any] = []T

var s Slice[int] = []int{1, 2, 3}

fmt.Println(s) // [1 2 3]
```

泛型别名适合给复杂类型起更短的名字，但不要过度使用，否则会降低可读性。

## 函数类型推断

**这一节是 Go 1.27 的新能力，初读可以跳过**——不写它也能正常调用泛型函数，只是少一种省略类型实参的场景。

Go 1.27 起，泛型函数在需要赋值给非泛型函数类型的上下文中可以自动推断类型实参。前提是目标类型必须是函数类型。

```go
func Map[S ~[]E, E, R any](s S, f func(E) R) []R {
    r := make([]R, 0, len(s))

    for _, v := range s {
        r = append(r, f(v))
    }

    return r
}
```

可以直接把泛型函数赋给函数变量，省略类型实参：

```go
var f func([]int, func(int) string) []string = Map
```

目标类型不是函数类型时不会做这种推断，赋给 `any` 这类接口类型仍然编译失败：

```go
var v any = Map

// cannot use generic function Map without instantiation
```

同理，`var v any = Identity` 会报 `cannot use generic function Identity without instantiation`。也就是说这种推断只在目标类型是函数类型时生效，其他赋值上下文仍然需要显式实例化。

也可以把泛型函数作为参数传递：

```go
func Map[S ~[]E, E, R any](s S, f func(E) R) []R {
    r := make([]R, 0, len(s))

    for _, v := range s {
        r = append(r, f(v))
    }

    return r
}

func UseMap(fn func([]int, func(int) string) []string) {
    result := fn([]int{1, 2}, func(v int) string {
        return fmt.Sprint(v * 2)
    })

    fmt.Println(result) // [2 4]
}

UseMap(Map)
```

这使得泛型函数在回调、适配器和函数式风格代码中更容易使用。

## 类型集合

接口作为约束时，描述的是**类型集合**——前面各节的约束 `Number`、`Integer`、`TildeInteger` 都是这个意思。集合元素来自两部分：

- **类型元素**：`~int | ~string` 这类联合（`~` 的含义见"联合约束与 `~`"一节）。
- **方法**：接口里列出的方法，要求类型实现它们。

两者可以同时写：

```go
type PrettyString interface {
    ~string
    String() string
}
```

`PrettyString` 的类型集合就是"底层类型是 `string`、并且实现了 `String() string` 的所有类型"。

一条边界要记牢：**带类型集合的接口只能当约束，不能当普通接口变量用。**

```go
type Ordered interface {
    ~int | ~float64 | ~string
}

// var v Ordered // 非法
// cannot use type Ordered outside a type constraint: interface contains type constraints
```

只有方法集合构成的基本接口（basic interface，例如 `interface{ String() string }`）才能作为普通类型使用；这一点在接口一侧的讨论见 `12-接口.md` 的"接口与泛型"一节：同一个接口写法，当约束用和当变量类型用，含义完全不同。

## 泛型与接口的取舍

泛型不是接口的替代品。

- 需要运行时多态、不同具体类型的行为时，用接口。
- 需要算法对多种类型复用，并且保持静态类型检查时，用泛型。
- 如果只有少量具体类型，直接写具体函数可能更简单。
- 泛型会增加类型签名复杂度，能明显减少重复时再使用。

## 泛型的实现与性能

**这一节是性能话题，初读可以跳过**——它回答的是"泛型会不会让二进制变大、会不会更快"，不影响怎么写对代码。

泛型如何编译是编译器的实现细节，语言规范不作规定，代码不应该依赖具体的实现策略。粗略地说，当前实现按类型实参的**形状（shape）**分组生成代码：形状相同的实例可以共用同一份生成的代码，因此给同一个泛型类型或函数传入不同实参，通常不会让代码量随实例数量线性增长。

实践中的几点经验：

- 泛型实例化后会针对具体类型实参生成代码，和手写该类型的函数走同样的编译流程；实际差异需要测量，用 `go test -bench`，不要凭直觉判断。
- 与基于接口的写法相比，泛型不需要把值装箱成接口，也不需要在调用点做动态派发，对数值、字符串这类小值通常有优势。
- 反过来，如果这些值本来就要以接口形式存在（例如要放进 `[]any`，或者需要运行期多态），改成泛型并不会消除装箱开销。
- 泛型的主要收益是可复用性和静态类型检查，不要为了“更快”而把清晰的接口设计改成泛型。

## Go 1.20 对 comparable 的放宽

**这一节讲的是规范细节，初读可以跳过**——只要记住"`comparable` 约束也接受 `any` 这类可比较的接口类型"就够了，等真的遇到"为什么 `map[any]int` 能塞进泛型函数"再回来看。

规范把“实现（implement）”和“满足（satisfy）”区分开，并明确 `comparable` 的类型集合是所有**严格可比较（strictly comparable）**的非接口类型。普通接口类型（例如 `any`）虽然可以用 `==` 比较，但它不是严格可比较的，因此它不实现 `comparable`。Go 1.20 起，这类类型可以“满足”`comparable` 约束：

```go
func Keys[K comparable, V any](m map[K]V) []K {
    ks := make([]K, 0, len(m))

    for k := range m {
        ks = append(ks, k)
    }

    return ks
}

m := map[any]int{"a": 1, 2: 2}

fmt.Println(len(Keys(m))) // 2
```

`any` 本身不实现 `comparable`，但因为它可比较，所以满足了约束，这段代码在 Go 1.20 之前是无法编译的。

代价是类型参数不再提供“比较一定安全”的保证：规范明确说明，由于这条例外，比较类型参数的操作数可能在运行期 panic。如果 `K` 实例化为 `any`，而动态值是切片，比较就会 panic。

严格可比较的定义可以这样记：

- 布尔、数字、字符串、指针、channel 类型严格可比较。
- 结构体在所有字段类型严格可比较时严格可比较，数组同理。
- 接口类型可比较，但不是严格可比较。
- 类型参数在类型集合中所有类型都严格可比较时严格可比较。

## 标准库泛型

标准库已经提供大量泛型函数，写自己的工具函数前先查一遍：
