# 31 编码与序列化

> Go 版本：>= 1.27.1  
> 相关标准库：encoding/base64、encoding/hex、encoding/binary、encoding/csv、encoding/xml、encoding/gob

这一篇把"把数据换成另一种表示"的几个标准库包放在一起：Base64 与十六进制负责把字节变成可打印文本，`encoding/binary` 负责定长二进制布局，CSV、XML、gob 是三种不同层次的序列化。

## encoding/base64

Base64 编码：

```go
encoded := base64.StdEncoding.EncodeToString([]byte("hello"))
fmt.Println(encoded) // aGVsbG8=
```

解码：

```go
data, err := base64.StdEncoding.DecodeString("aGVsbG8=")
if err != nil {
    return err
}

fmt.Println(string(data)) // hello
```

URL 安全场景可以使用 `base64.URLEncoding`。

和 JSON 的交界：`encoding/json` 会把 `[]byte` 编码成 Base64 字符串（v2 里定长数组 `[N]byte` 也一样），所以从 JSON 取回的字节串要先 Base64 解码——两条规则的对照见 `26-JSON与序列化.md` 的“v1 与 v2 的差异”一节。

## encoding/hex

`encoding/hex` 做十六进制编码，常用于把摘要、密钥、随机字节打印或存成字符串：

```go
s := hex.EncodeToString([]byte("hello"))
fmt.Println(s) // 68656c6c6f

b, err := hex.DecodeString("68656c6c6f")
if err != nil {
    return err
}

fmt.Println(string(b)) // hello
```

`DecodeString` 只接受十六进制字符且长度必须为偶数，否则返回错误：

```go
_, err := hex.DecodeString("zz")
fmt.Println(err) // encoding/hex: invalid byte: U+007A 'z'
```

需要流式处理时用 `hex.NewEncoder` 和 `hex.NewDecoder`。只做一次性输出时，`fmt.Printf("%x", b)` 和 `hex.EncodeToString` 等价，选一个保持一致即可。

## encoding/binary

`encoding/binary` 在定长数值和字节序列之间转换，适合自己定义的二进制协议、文件格式和网络协议的头部。

`binary.Read` 和 `binary.Write` 除了目标 Reader/Writer，还需要两个参数：字节序和指向定长值的指针。字节序用 `binary.BigEndian`、`binary.LittleEndian`，本机字节序是 `binary.NativeEndian`：

```go
buf := new(bytes.Buffer)

if err := binary.Write(buf, binary.LittleEndian, uint32(1)); err != nil {
    return err
}

fmt.Printf("% x\n", buf.Bytes()) // 01 00 00 00

var n uint32
if err := binary.Read(buf, binary.LittleEndian, &n); err != nil {
    return err
}

fmt.Println(n) // 1
```

结构体可以整体读写，字段按声明顺序排列；字段必须是导出字段，字段名写 `_` 表示跳过（相当于 padding）：

```go
type header struct {
    Magic uint32
    Ver   uint16
    _     uint16 // padding
}

var b bytes.Buffer
if err := binary.Write(&b, binary.BigEndian, header{Magic: 0x474f, Ver: 1}); err != nil {
    return err
}

fmt.Printf("% x\n", b.Bytes()) // 00 00 47 4f 00 01 00 00
```

`binary` 只处理**定长**类型：`string`、`[]string` 这类变长类型会直接报错，而元素定长的切片（如 `[]uint32`）是支持的，长度由切片本身决定。

```go
var s string

err := binary.Read(strings.NewReader("abc"), binary.BigEndian, &s)
fmt.Println(err) // binary.Read: invalid type *string
```

包里还有一组变长整数编码（`PutUvarint`/`Uvarint`/`Varint`，protobuf 用的就是 varint）。它只在实现自定义二进制协议时才用得上，注意 `Uvarint` 的第二个返回值必须检查（`>0` 成功、`0` 缓冲太小、`<0` 溢出 64 位），`PutUvarint` 缓冲不够会 panic。

`encoding/binary` 只负责字节序和定长布局，不解决格式演进——要在几种序列化之间选型，看文末的对照表。

## encoding/csv

读写 CSV：

```go
records := [][]string{
    {"name", "age"},
    {"Tom", "18"},
}

writer := csv.NewWriter(os.Stdout)
defer writer.Flush()

for _, record := range records {
    if err := writer.Write(record); err != nil {
        return err
    }
}
```

读取：

```go
reader := csv.NewReader(os.Stdin)

records, err := reader.ReadAll()
if err != nil {
    return err
}

fmt.Println(records) // 取决于 stdin 里的 CSV：每个记录是一个 []string，如 [[name age] [Tom 18]]
```

## encoding/xml

`xml.Marshal` 和 `xml.Unmarshal` 处理 XML，结构体标签的写法和 `encoding/json` 类似但语义更多。

最常用的两个标签选项是 `,attr`（作为属性而不是子元素）和 `,chardata`（作为字符数据而不是元素）：

```go
type Server struct {
    XMLName xml.Name `xml:"server"`
    Name    string   `xml:"name,attr"`
    Addr    string   `xml:"addr"`
}

s := Server{Name: "web", Addr: "127.0.0.1:8080"}

data, err := xml.Marshal(s)
if err != nil {
    return err
}

fmt.Println(string(data))
// <server name="web"><addr>127.0.0.1:8080</addr></server>
```

`XMLName` 字段用来固定元素名（不写时取结构体名或字段标签）。反序列化：

```go
var s Server

err := xml.Unmarshal([]byte(`<server name="db"><addr>1.2.3.4</addr></server>`), &s)
if err != nil {
    return err
}

fmt.Println(s.Name, s.Addr) // db 1.2.3.4
```

`xml.Unmarshal` 只写入导出字段，元素名匹配是**大小写敏感**的。

`xml:",chardata"` 把一个字段当作元素的文本内容：

```go
type Title struct {
    XMLName xml.Name `xml:"title"`
    Lang    string   `xml:"lang,attr"`
    Text    string   `xml:",chardata"`
}

b, err := xml.Marshal(Title{Lang: "zh", Text: "Go 语言"})
if err != nil {
    return err
}

fmt.Println(string(b)) // <title lang="zh">Go 语言</title>
```

其他可用的标签选项：`",omitempty"` 在字段为空值时省略、`",innerxml"` 原样嵌入、`",cdata"` 包一层 `<![CDATA[ ]]>`、`"-"` 忽略字段、`"a>b>c"` 表示嵌套层级。

这里说的"空"是 false、0、nil 指针或接口、长度为零的 array/slice/map/string——**零值 `time.Time` 和零值结构体都不算空**（实测不会被省略），这与 JSON v1 的 `omitempty` 是同一个坑，见 `26-JSON与序列化.md` 的“omitempty 和 omitzero 的区别”一节。

格式化输出用 `xml.MarshalIndent`：

```go
data, err := xml.MarshalIndent(s, "", "  ")
```

`encoding/xml` 的 `Marshal` 会省略 XML 声明，需要时手动拼上常量 `xml.Header`。处理超大 XML 不要用 `Unmarshal` 一次性读入，改用 `xml.NewDecoder` 的 `Decode` 或 `Token` 流式处理。

```go
dec := xml.NewDecoder(r)

for {
    tok, err := dec.Token()
    if err == io.EOF {
        break
    }
    if err != nil {
        return err
    }

    fmt.Println(tok) // 输出取决于 r 里的 XML；注意 CharData 是 []byte，直接打印会得到 [120] 这样的字节值
}
```

同样是"按 token 流式读"，JSON 侧的对应物是 `jsontext` 的 `ReadToken` / `ReadValue`（见 `26-JSON与序列化.md` 的“读取 Token”一节）。

## encoding/gob

`gob` 是 Go 自己的二进制序列化格式，只在 Go 程序之间使用。它的特点是自描述：类型信息随流一起发送，接收端按**字段名**匹配。

```go
type Point struct {
    X, Y int
}

var buf bytes.Buffer

enc := gob.NewEncoder(&buf)
if err := enc.Encode(Point{X: 1, Y: 2}); err != nil {
    return err
}

var p Point
dec := gob.NewDecoder(&buf)
if err := dec.Decode(&p); err != nil {
    return err
}

fmt.Println(p) // {1 2}
```

适合 gob 的场景：Go 进程之间的 RPC（`net/rpc` 就是用 gob）、同构服务之间传输已经定义好的 Go 值、本地缓存里需要快速编解码的自有结构。同一个 `Encoder` 连续发送多个值时，类型信息只发送一次：

```go
var buf bytes.Buffer
enc := gob.NewEncoder(&buf)

if err := enc.Encode(Point{X: 1, Y: 2}); err != nil {
    return err
}
first := buf.Len() // 第一个值带着类型定义，明显更大

if err := enc.Encode(Point{X: 3, Y: 4}); err != nil {
    return err
}

fmt.Println(first)             // 40 上下：类型定义只发一次，但计在第一个值里
fmt.Println(buf.Len() - first) // 8 上下：之后每个同类型的值只有几字节
```

具体字节数取决于字段类型和取值（gob 的整数是变长编码）。

它的限制同样来自“自描述 + Go 专有”：

- 只能 Go 到 Go，其他语言没有 gob 实现，所以不能当作对外协议或长期持久化格式
- 只编码导出字段；`chan`、`func` 类型字段被忽略，顶层的 `func`、`chan` 直接报错
- 不传指针，只传指针指向的值，`nil` 指针无法编码；带环的递归值也有问题
- 接收端按字段名匹配：多出的字段被忽略、缺少的字段被丢弃，所以字段改名会静默丢数据
- 类型信息带来额外开销，追求极致紧凑时不如手写二进制格式
- 解码不可信输入要谨慎：`Decoder` 只做基本的尺寸检查，且这些限制不可配置

以接口类型传输具体值时，收发两侧都要注册：

```go
gob.Register(Point{})
```

`gob.Register` 在类型名和类型之间建立一一对应关系，名字冲突会 panic，通常在 `init` 里调用；重复注册同一个类型不会出错。

### 该用 gob、JSON 还是 protobuf

三种序列化方式的取舍，本质是"两端是不是同一个 Go 程序"和"要不要能被人和设备读"：

| 场景 | 用什么 | 理由 |
| --- | --- | --- |
| Go 进程之间传已定义好的值（RPC、内部缓存） | **gob** | 类型信息随流发送，不用手写标签；跨语言时立刻作废 |
| 对外接口、配置文件、需要人能读能改 | **JSON** | 文本、跨语言、工具链齐全（v1/v2 与 `jsontext` 的选择见 `26-JSON与序列化.md`） |
| 跨语言且要 schema 演进与代码生成 | **protobuf 等第三方** | gob 不解决演进，JSON 可选字段要靠自己约定；标准库不提供 |

两条容易搞反的：**"性能"不是选 gob 的主要理由**——`encoding/binary` 手写定长布局更快，gob 省的是"写标签 + 处理类型"这件事；**"能存就行"也不该选 gob**——它的格式与 Go 版本、类型定义绑定，长期持久化的数据用 JSON 或自己定义的定长格式更稳。
